# 20-多渠道通知操作指南

> 对应路线图：`ROADMAP.md` § 4.0 阶段 0「0.6 多渠道通知」。
> 适用版本：iBoot 1.0.0。
> 本文面向开发、测试和运维人员，说明通知渠道的配置、使用、验收与排障。

---

## 1. 能力概览

当前支持四个通知渠道：

| 渠道 | 实现 | 默认状态 | 说明 |
|---|---|---|---|
| 站内 | `sys_message` + `sys_message_receiver` + SSE | 启用 | 未读消息进入右上角铃铛，可打开“我的消息”弹窗 |
| 邮件 | Spring Mail + QQ/163 SMTP | 启用（需配置 SMTP） | 收件人取 `sys_user.email` |
| 钉钉 | 群自定义机器人 Webhook + 加签 | 启用（需配置 Webhook） | 单机器人 20 条/分钟限流 |
| 短信 | 阿里云 Dysmsapi | **关闭** | 个人实名资质无法完成国内短信签名报备；代码保留，默认不登记、不发送 |

首个业务事件是**审批待办**：申请人提交请假后，审批人通过站内、邮件、钉钉三个真实渠道收到通知。

核心数据：

- `sys_message`：站内消息主表，新增 `business_type` 标识业务跳转类型（如 `APPROVAL_TODO`）。
- `sys_message_receiver`：用户收件记录、已读状态。
- `sys_notification_delivery`：按“事件 × 渠道 × 接收人”拆分的投递记录，包含状态、尝试次数、下次重试时间和最后错误。
- `sys_message_template`：通知文案模板，审批待办使用 `APPROVAL_TODO`。
- Quartz 任务 `notificationRetryTask.retry`：每分钟扫描到期投递并重试。

## 2. 快速开始

### 2.1 环境要求

- JDK 25
- Maven 3.9+
- MySQL 8.0.45、Redis 7.x
- 前端 Node.js 16+ 与 `cnpm`
- 可选：Docker（运行中间件与 Testcontainers 测试）

### 2.2 配置本地环境变量

仓库根目录已提供 `.env.example`。复制为 `.env` 后填写真实值：

```bash
cp .env.example .env
chmod 600 .env
```

`.env` 已被 `.gitignore` 忽略，不要提交。

Spring Boot **不会自动读取** `.env`，启动前需要加载：

```bash
set -a
source .env
set +a
mvn -s /home/lam/repo/settings.xml -pl iboot-admin spring-boot:run
```

也可以在 IDE 的 Run Configuration 中配置同样的环境变量。

### 2.3 主要配置项

| 变量 | 用途 | 示例 |
|---|---|---|
| `MAIL_HOST` | SMTP 主机 | `smtp.qq.com` |
| `MAIL_PORT` | SMTP 端口 | `465` |
| `MAIL_USERNAME` | 发件邮箱 | `xxx@qq.com` |
| `MAIL_PASSWORD` | 邮箱授权码，不是登录密码 | `********` |
| `MAIL_FROM` | 发件人地址 | `xxx@qq.com` |
| `MAIL_SSL_ENABLED` | 是否使用 SSL | `true` |
| `MAIL_STARTTLS_ENABLED` | 是否使用 STARTTLS | `false` |
| `IBOOT_DINGTALK_ENABLED` | 是否启用钉钉 | `true` |
| `IBOOT_DINGTALK_WEBHOOK` | 钉钉机器人 Webhook | `https://oapi.dingtalk.com/robot/send?access_token=...` |
| `IBOOT_DINGTALK_SECRET` | 钉钉加签 Secret | `SEC...` |
| `IBOOT_SMS_ENABLED` | 是否启用短信 | 保持 `false` |
| `IBOOT_NOTIFICATION_RETRY_MAX` | 最大尝试次数 | `5` |
| `IBOOT_NOTIFICATION_RETRY_BACKOFF_SECONDS` | 基础退避秒数 | `60` |

所有密钥只通过环境变量注入，不写入 `application.yml`、数据库或日志。

## 3. 邮件渠道配置

### 3.1 QQ 邮箱

1. 登录 `https://mail.qq.com`。
2. **设置 → 账号**。
3. 找到 **POP3/IMAP/SMTP/Exchange/CardDAV/CalDAV 服务**。
4. 开启 **IMAP/SMTP 服务**，完成手机验证。
5. 生成 **授权码**，保存到 `.env` 的 `MAIL_PASSWORD`。

SMTP 参数：

```text
MAIL_HOST=smtp.qq.com
MAIL_PORT=465
MAIL_SSL_ENABLED=true
MAIL_STARTTLS_ENABLED=false
```

### 3.2 163 邮箱

1. 登录 `https://mail.163.com`。
2. **设置 → POP3/SMTP/IMAP**。
3. 开启 **SMTP 服务**，完成手机验证。
4. 获取 **授权码**（部分版本叫“客户端授权密码”）。

SMTP 参数：

```text
MAIL_HOST=smtp.163.com
MAIL_PORT=465
MAIL_SSL_ENABLED=true
MAIL_STARTTLS_ENABLED=false
```

### 3.3 连通性检查

```bash
printf '' | openssl s_client -connect smtp.qq.com:465 -servername smtp.qq.com 2>/dev/null | head -3
```

看到 `220 ...` 开头即正常。

### 3.4 注意事项

- 必须使用授权码，不是邮箱登录密码。
- 个人邮箱有每日发信限额，只适合开发测试。
- 个人邮箱无法控制 SPF/DKIM，发到外部邮箱可能进入垃圾箱；测试时先发给自己。
- 收件人邮箱为空时，站内消息仍会创建，邮件投递记录为 `SKIPPED`，不会重试。

## 4. 钉钉渠道配置

1. 创建或进入一个钉钉群。
2. **群设置 → 智能群助手 → 添加机器人 → 自定义**。
3. 机器人名称填 `iBoot 通知`。
4. 安全设置选择 **加签**，保存 Secret。
5. 复制 Webhook 地址，填入 `.env`：

```text
IBOOT_DINGTALK_ENABLED=true
IBOOT_DINGTALK_WEBHOOK=https://oapi.dingtalk.com/robot/send?access_token=...
IBOOT_DINGTALK_SECRET=SEC...
```

限制与注意事项：

- 每个机器人每分钟最多 20 条，超限会被限流 10 分钟。系统使用 Guava 限流，超限进入重试。
- 加签时间戳与钉钉服务器时间差需在 1 小时内，服务器需开启 NTP。
- 消息正文默认带 `【iBoot】` 前缀，兼容同时启用“自定义关键词”的机器人。
- Webhook 和 Secret 按密钥管理，不要提交到仓库。

## 5. 短信渠道

### 5.1 当前状态

短信适配器已实现，但默认关闭：

```yaml
iboot:
  notification:
    sms:
      enabled: false
```

关闭时**不会创建短信投递记录**，也不会调用阿里云 API。

原因：阿里云自 2025-06-06 起不再接受个人实名账号申请国内短信自用资质；国内短信签名必须使用企业或个体工商户资质并完成运营商实名报备。

### 5.2 以后启用步骤

1. 企业或个体工商户实名认证。
2. 申请自用资质（或个人可用的其他合规路径）。
3. 申请签名，完成运营商实名报备（通常 5–10 个工作日）。
4. 申请通知短信模板。
5. 创建 RAM 用户，授予最小短信权限，获取 AccessKey。
6. 配置 `IBOOT_SMS_*`，把 `IBOOT_SMS_ENABLED` 改为 `true`。

切换短信渠道不需要改代码，只改配置和模板数据。

### 5.3 不要做的事

- 不要使用所谓“免报备、免资质、个人可用”的第三方短信接口。
- 不要使用主账号 AccessKey。
- 不要把 AccessKey、签名、模板 Code 写入仓库。
- 不要伪造短信发送成功结论。

## 6. 使用站内通知

### 6.1 产生一条审批待办

1. 登录管理端。
2. 进入 **审批中心 → 发起请假**。
3. 选择审批人并提交。
4. 审批人会收到站内、邮件、钉钉通知；短信默认关闭。

### 6.2 右上角铃铛

铃铛是**当前用户的未读收件箱预览**：

- 登录后从服务端加载最多 10 条未读消息。
- 在线时通过 SSE 实时插入新消息。
- 显示标题、内容、相对时间、优先级标签。
- 审批待办消息点击后跳转 **审批中心**。
- 其他消息点击后打开 **“我的消息”弹窗**。
- “查看全部消息”打开个人收件箱，支持全部/未读/已读筛选、分页、标记已读和删除。

### 6.3 消息与投递记录的区别

| 页面 | 位置 | 用途 |
|---|---|---|
| 我的消息 | 铃铛弹窗 | 当前用户的消息内容、已读状态、删除 |
| 消息中心 → 消息管理 | 消息管理菜单 | 管理员管理全局消息、撤回 |
| 通知投递 | 消息管理菜单 | 查看每个渠道的成功/失败、尝试次数、最后错误并重试 |

## 7. 通知投递管理

### 7.1 入口

**消息管理 → 通知投递**，访问路径 `/dashboard/delivery`。

### 7.2 列表字段

- 记录 ID
- 事件 ID / 事件类型
- 渠道：`IN_APP`、`EMAIL`、`DINGTALK`、`SMS`
- 接收人（邮箱/手机号脱敏）
- 消息标题
- 状态
- 尝试次数 / 最大次数
- 下次重试时间
- 最后错误（已脱敏）
- 创建时间

### 7.3 状态说明

| 状态 | 含义 |
|---|---|
| `PENDING` | 已登记，等待发送或重试 |
| `SENDING` | 已被执行者领取，正在发送 |
| `SUCCESS` | 发送成功 |
| `FAILED` | 本次失败，仍有自动重试机会 |
| `DEAD` | 达到最大尝试次数，等待人工处理 |
| `SKIPPED` | 缺少接收地址或渠道关闭，不重试 |

### 7.4 筛选

支持按状态、渠道、接收人、事件类型筛选，并支持分页。

### 7.5 失败重试

- 自动重试：Quartz 每分钟扫描到期记录，按指数退避重试，默认最多 5 次。
- 人工重试：`FAILED` / `DEAD` 记录可在列表中点击“重试”，确认后立即重新投递。
- 失败原因会脱敏保存，例如 `access_token=***`。

## 8. 验收与排障

### 8.1 正常链路验收

1. 审批人配置真实邮箱，钉钉机器人可用。
2. 提交一条请假申请。
3. 在通知投递页确认同一事件生成三条记录：站内、邮件、钉钉均为 `SUCCESS`，没有短信记录。
4. 审批人登录后可在铃铛看到未读审批待办，点击进入审批中心。
5. 检查邮箱和钉钉群实际收到消息。

### 8.2 失败链路验收

1. 临时把 `IBOOT_DINGTALK_SECRET` 改错并重启后端。
2. 提交一条请假，钉钉记录应为 `FAILED`，最后错误已脱敏。
3. 恢复 Secret 并重启，在通知投递页点击“重试”，状态应变为 `SUCCESS`。

### 8.3 缺少邮箱

审批人 `sys_user.email` 为空时：

- 站内、钉钉正常投递。
- 邮件记录为 `SKIPPED`，不进入重试。

### 8.4 常见问题

**Q：`mvn spring-boot:run` 下 Quartz 任务报 `ClassCastException`？**

这是 devtools restart classloader 的既有问题，影响所有 Quartz 任务。验证定时任务请使用打包后的 jar：

```bash
mvn -s /home/lam/repo/settings.xml -pl iboot-admin -am -DskipTests package
java -jar iboot-admin/target/iboot-admin-1.0.0.jar
```

**Q：Testcontainers 报无法拉取 `testcontainers/ryuk`？**

本机 Docker Hub 拉取受限时，指定本地已有镜像：

```bash
TESTCONTAINERS_RYUK_CONTAINER_IMAGE=testcontainers/ryuk:0.12.0 \
  mvn -s /home/lam/repo/settings.xml verify
```

**Q：页面时间显示 `Invalid Date`？**

CloudEvents 响应中的 `LocalDateTime` 可能被序列化为 `[年,月,日,时,分,秒]` 数组。前端使用 `formatDateTime` 兼容 ISO 字符串和数组。

**Q：菜单点击后空白？**

侧边栏只取菜单路径最后一段作为路由。例如菜单路径 `/notification/delivery` 映射到 `/dashboard/delivery`，前端子路由必须是 `delivery`。

**Q：`mvn spring-boot:run` 读不到 `.env`？**

Spring Boot 不会自动读取 `.env`，请使用 `set -a; source .env; set +a` 或在 IDE 中配置环境变量。

**Q：Actuator `/env` 会泄露密钥吗？**

Spring Boot 默认会脱敏含 `password`、`secret`、`key`、`token` 的配置。仍建议本地移除 `env` 端点或修改默认 Basic Auth 密码，日志中不要打印密钥和完整邮箱/手机号。
