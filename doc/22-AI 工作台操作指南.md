# AI 工作台操作指南

> 对应能力：ROADMAP 1.1「AI 底座与智能对话」+ 1.2「知识库 RAG 与权限一致性」
> 对应变更：`openspec/changes/add-ai-chat-foundation`
> 最后更新：2026-10-25

## 1. 服务概览

`iboot-ai` 是独立于 `iboot-admin` 的 Spring Boot 服务，默认监听 **8081**，提供：

- 多轮流式对话（SSE，默认关闭深度思考）
- Redis 会话记忆与用户会话列表
- 每日 token 配额（全局 + 单用户）
- token / 首 token 延迟 / 错误率指标与告警
- 知识库 RAG：上传、解析、分块、Embedding、BM25 + kNN + 应用层 RRF、引用溯源（1.2）

1.2 起承载知识库 RAG 与文本类 PDF/Word 解析；Agent 编排与知识图谱属于 1.3 / 1.4，图谱名称解析属于 1.5。

## 2. 启动

### 2.1 前置条件

- JDK 25、Maven 3.9+
- Redis 7.x（会话、聊天记忆、配额、登录态共享）
- `iboot-admin` 已启动（签发登录令牌）
- 百炼 API Key 与端点

### 2.2 环境变量

`iboot-ai` 读取以下变量（写入根目录 `.env`，该文件已被 `.gitignore` 忽略）：

```ini
DASHSCOPE_CHAT_API_KEY=sk-...
DASHSCOPE_EMBEDDING_API_KEY=sk-...
DASHSCOPE_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode
JWT_SECRET=与 iboot-admin 相同的密钥
```

> `JWT_SECRET` 必须与 `iboot-admin` 的 `jwt.secret` 完全一致，否则无法读取共享会话。

### 2.3 启动命令

```bash

```

或使用打包产物：

```bash

```

健康检查：

```bash

```

`iboot-portal` 的 Vite 代理已配置 `/iboot/ai` → `http://localhost:8081`，并重写为 `/api/ai`：


## 3. 配置说明

| 配置 | 默认值 | 说明 |
|---|---|---|
| `spring.ai.openai.chat.options.model` | `qwen3.8-flash` | 对话模型；可用 `IBOOT_AI_CHAT_MODEL` 覆盖 |
| `spring.ai.openai.chat.options.extra-body.enable_thinking` | `false` | **必须保持 false**，否则首 token 延迟与 token 成本显著上升 |
| `spring.ai.openai.chat.base-url` | `${DASHSCOPE_BASE_URL}/v1` | **必须含 `/v1`**，starter 会自行拼接 `/chat/completions` |
| `spring.ai.openai.chat.options.max-tokens` | `4096` | 单次回答上限 |
| `iboot.ai.quota.global-daily-tokens` | `20000000` | 全局每日 token 上限 |
| `iboot.ai.quota.user-daily-tokens` | `200000` | 单用户每日 token 上限 |
| `iboot.ai.chat.max-messages` | `20` | 会话记忆窗口 |
| `iboot.ai.chat.conversation-ttl-hours` | `24` | 会话与消息保留时间 |
| `iboot.ai.chat.sse-timeout-ms` | `300000` | SSE 连接超时 |
| `iboot.ai.chat.heartbeat-ms` | `20000` | SSE 心跳间隔 |

### 3.1 为什么 base-url 必须带 /v1

OpenAI starter 会在 base-url 后追加 `/chat/completions`。填

```
https://dashscope.aliyuncs.com/compatible-mode
```

会得到 404；正确写法是：

```
https://dashscope.aliyuncs.com/compatible-mode/v1
```

服务启动时会校验该后缀，不满足直接失败。

### 3.2 为什么必须显式关闭 thinking

`qwen3.8-flash` 的 thinking 默认开启。Spike 实测：

| 配置 | 首 token p95 | completion tokens |
|---|---|---|
| 关闭 thinking | 0.74–0.98 s | 16 |
| 默认（开启） | 3.0–4.4 s | 75（其中 50 reasoning） |

不关闭会直接违反「首 token < 3 s」的验收判据，并把成本抬高约 5 倍。

## 4. 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/ai/chat` | 非流式对话 |
| POST | `/api/ai/chat/stream` | 流式对话（`text/event-stream`） |
| GET | `/api/ai/conversations` | 当前用户会话列表 |
| GET | `/api/ai/conversations/{id}/messages` | 会话消息 |
| GET | `/api/ai/usage` | 当天用量与剩余配额 |

### 4.1 流式事件

| 事件 | 数据 | 说明 |
|---|---|---|
| `meta` | `{conversationId}` | 首帧，标识会话 |
| `token` | `{delta}` | 增量文本 |
| `done` | `{conversationId, model, usage}` | 正常结束，带 token 用量 |
| `error` | `{code, message, retryable}` | 异常结束，不再发送 `done` |

**注意**：流式 usage 位于 `choices: []` 的最后一个 chunk，客户端不得把空 choices 当作结束，必须以 `done` / `error` / 流关闭为准。

### 4.2 示例

```bash
TOKEN="<admin 登录返回的 token>"

curl -N http://localhost:8081/api/ai/chat/stream \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"content":"只回复两个字：收到"}'
```

## 5. 鉴权

`iboot-ai` 不签发令牌，只复用 `iboot-admin` 的登录态：

1. 校验 JWT 签名（共享 `jwt.secret`）；
2. 读取 Redis `login_tokens:<token>`；
3. 把 `userId`、`permissions`、`deptId` 写入安全上下文；
4. 按 admin 的滑动过期语义刷新 `login_tokens:*` 与 `online_token:*` 的 TTL。

白名单只有 `/actuator/health` 与 `/actuator/prometheus`。

## 6. 配额与成本

- 计数 key：`iboot:ai:quota:global:{yyyy-MM-dd}`、`iboot:ai:quota:user:{userId}:{yyyy-MM-dd}`。
- 统计时区：北京时间自然日；key 保留 48 小时。
- 调用前检查当前值，超限直接返回 429，不调用模型；调用后按 usage 累加。
- 并发下允许小幅超额，建议预留 5% 余量。

### 6.1 429 补测条件

Spike 阶段尝试把百炼月度预算调到 ¥0.01 并触发熔断，但请求仍返回 200。原因是 `qwen3.8-flash` 免费额度仍有约 995K，免费调用不产生费用，预算统计不到支出。

补测条件（任一满足即可）：

1. 免费额度耗尽；
2. 使用没有免费额度的模型或地域（如新加坡）；
3. 在应用层直接构造超限场景（单元测试已覆盖）。

补测时记录真实的 429 状态码与错误体，更新到本指南与实现测试。

## 8. 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动失败，提示 `base-url 必须以 /v1 结尾` | 配置缺少 `/v1` | 修正 `DASHSCOPE_BASE_URL` 或 YAML |
| 启动失败，`OpenAiAudioSpeechModel` 缺少凭据 | 未提供全局 `spring.ai.openai.api-key` | 设置全局 Key，或关闭未使用的 audio/image 自动配置 |
| 模型返回 401 | Key 与地域不匹配、Key 失效 | 确认北京地域的 `sk-` Key |
| 模型返回 404 | base-url 路径错误 | 必须为 `.../compatible-mode/v1` |
| 首 token 超过 3 秒 | thinking 未关闭 | 设置 `enable_thinking=false` |
| 返回 429 | 应用层配额用尽 | 查 `/api/ai/usage`；次日重置或调高配额 |
| SSE 无增量 | 代理缓冲或客户端解析错误 | 确认未把空 `choices` 当结束；检查代理是否缓冲 |
| 会话列表为空 | 会话索引 TTL 到期或用户无会话 | 正常现象；发起新对话即可 |
| 认证 401 | `JWT_SECRET` 与 admin 不一致，或会话已登出 | 对齐密钥并重新登录 |

## 10. 已知限制

- 1.1 以独立 JVM 运行，**不做容器化**；Dockerfile 与 compose 属于阶段 3.1。
- 会话记忆使用自定义 Redis 仓储：官方 starter 依赖 RediSearch/RedisJSON，标准 `redis:7.0.14` 不具备。
- 智能对话与知识库视图为纯文本；智能体对话支持 Markdown 渲染（标题、列表、表格、代码块）。不支持语音与多模态输入。
- 深度思考固定关闭，暂不提供按会话开关。
- 1.2 起 `iboot-ai` 启动前置新增 MySQL（`iboot_ai`）与 Elasticsearch；纯对话路径不查询它们，但 Flyway 与索引初始化会在启动时执行。
- RAG 使用应用层 RRF（ES 基础许可证不含原生 RRF）；OCR 默认关闭，启用后扫描页会发送到云端。
- 1.3 新增智能体编排（见 §12），知识图谱属于 1.4，图谱名称解析属于 1.5。

## 11. 知识库 RAG（1.2）

### 11.1 前置条件

| 依赖 | 要求 |
|---|---|
| MySQL | 8.0.45，独立 schema `iboot_ai` |
| Elasticsearch | 9.2.3，索引 `iboot-kb-chunk-v1`（启动时幂等创建） |
| MinIO | bucket `iboot-ai`，知识库原文件存储 |
| admin | 已执行 Flyway `V25`，并提供 `GET /api/auth/scope` |
| 百炼 | Embedding Key；OCR 可选 `qwen3.5-ocr` |

本地一次性操作：

```bash
docker exec iboot-mysql mysql -uroot -proot \
  -e "CREATE DATABASE IF NOT EXISTS iboot_ai CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
docker exec iboot-minio /usr/bin/mc alias set local http://localhost:9000 minioadmin minioadmin
docker exec iboot-minio /usr/bin/mc mb --ignore-existing local/iboot-ai
```

迁移 `V25` 后必须**重新登录**，否则会话里没有 `ai:kb:query` / `ai:kb:manage` 权限。

### 11.2 环境变量

```ini
MYSQL_HOST=localhost
MYSQL_PORT=3306
MYSQL_USERNAME=root
MYSQL_PASSWORD=root
IBOOT_AI_MYSQL_DATABASE=iboot_ai
ELASTICSEARCH_URIS=http://localhost:9200
IBOOT_AI_MINIO_ENDPOINT=http://localhost:9000
IBOOT_AI_MINIO_ACCESS_KEY=minioadmin
IBOOT_AI_MINIO_SECRET_KEY=minioadmin
IBOOT_AI_MINIO_BUCKET=iboot-ai
IBOOT_AI_SCOPE_URL=http://localhost:8080/api/auth/scope
IBOOT_AI_RAG_ENABLED=true
# OCR 默认关闭；启用时填 Key
IBOOT_AI_OCR_ENABLED=false
IBOOT_AI_OCR_MODEL=qwen3.5-ocr
DASHSCOPE_OCR_API_KEY=
```

启动 `iboot-ai` 时 Flyway 自动创建四张表：`ai_knowledge_base`、`ai_kb_share_dept`、`ai_document`、`ai_document_chunk`。

| POST | `/api/ai/rag/chat` | `ai:kb:query` |
| POST | `/api/ai/rag/chat/stream` | `ai:kb:query` |
| GET/POST | `/api/ai/knowledge-bases` | `ai:kb:query` / `ai:kb:manage` |
| GET/PUT/DELETE | `/api/ai/knowledge-bases/{id}` | 查询 / 管理 |
| POST | `/api/ai/knowledge-bases/{kbId}/documents` | `ai:kb:manage` |
| GET | `/api/ai/knowledge-bases/{kbId}/documents` | `ai:kb:query` |

RAG 流式事件：`meta → citations → token* → done`；异常为 `error`。`citations` 数组包含 `index / kbId / docId / docTitle / pageNo / chunkIndex / snippet`。

### 11.4 权限模型

- 知识库可见范围：1 全部、2 自定义部门、3 本部门、4 本部门及以下、5 仅本人。
- 文档数据权限：SELF / DEPT / DEPT_AND_CHILD / CUSTOM / ALL，由 admin `scope` 接口提供。
- 检索时两路都带同一套 `kbId + ownerUserId/ownerDeptId` 前置过滤；权限范围服务不可用时返回 503，不降级为不过滤。
- 本地红队账号（仅开发环境，密码 `admin123`）：
  - `rag_self`：SELF
  - `rag_dept`：DEPT
  - `rag_custom`：CUSTOM

### 11.5 OCR

- 默认关闭；只对没有可提取文本的页面调用，文本页不送云。
- 模型 `qwen3.5-ocr`，OpenAI 兼容 `image_url`；单页 150 DPI、最长边 2048px。
- 日页数配额 `iboot.ai.rag.ocr.daily-page-limit`（默认 200），超限文档失败为 `OCR_QUOTA`。
- 启用需要 `DASHSCOPE_OCR_API_KEY`；启动时缺少 Key 会直接失败。

### 11.7 说明与排障

| 现象 | 原因 | 处理 |
|---|---|---|
| 403 `knowledge_access_denied` | 知识库不可见、非所有者修改或缺少 `ai:kb:*` 权限 | 重新登录；确认 V25 已授权到当前角色 |
| 403 缺少权限 | 会话中没有 `ai:kb:query/manage` | 在 admin 角色菜单中授权后重新登录 |
| 503 `retrieval_unavailable` | scope 接口或 Elasticsearch 不可用 | 检查 admin 与 ES；系统按失败关闭处理 |
| 文档 `FAILED` `NO_TEXT` | 扫描件且 OCR 未启用 | 启用 OCR 后重试 |
| 文档 `FAILED` `OCR_QUOTA` | 日页数配额耗尽 | 次日重试或调高配额 |
| 文档 `FAILED` `DIMENSION_MISMATCH` | Embedding 维度与索引不一致 | 对齐 `text-embedding-v4` 1024 维并重建索引 |
| 检索结果为空 | 可见知识库为空、权限过滤或文档未就绪 | 检查文档状态与 scope 返回 |

**为什么是应用层 RRF**：ES 9.2.3 基础许可证不包含原生 RRF，服务端会返回 `security_exception`；因此 BM25 与 kNN 分别查询，再按 `1/(60+rank)` 在应用层融合，两路使用完全相同的权限过滤。

## 12. 智能体编排（1.3）

### 12.1 能力概览

智能体在对话基础上增加了受控的工具调用：模型可以从登记过的工具中选择，以**当前用户身份**代理调用 admin 接口，并在写操作前停下来等待确认。运行轨迹可审计，行为可回测。

默认**关闭**，需要显式开启：

```ini
IBOOT_AI_AGENT_ENABLED=true
IBOOT_AI_AGENT_ADMIN_BASE_URL=http://localhost:8080
IBOOT_AI_AGENT_MAX_STEPS=6
IBOOT_AI_AGENT_APPROVAL_TTL_SECONDS=300
```

### 12.2 前置条件

| 依赖 | 要求 |
|---|---|
| admin | 已执行 Flyway `V26`，并提供 `ai:agent:use` / `ai:agent:manage` 权限 |
| 统计权限 | 统计接口已收紧为 `report:view` / `usage:view` |
| 模型 | 支持 Function Calling（`qwen3.8-flash` 已实测） |

菜单授权后需要**重新登录**，会话中的权限才会刷新。

### 12.3 工具清单

| 工具 | 下游接口 | 权限 | 类型 |
|---|---|---|---|
| `query_users` | `GET /api/user/list` | `user:list` | 只读 |
| `query_login_logs` | `GET /api/log/login/list` | `loginlog:list` | 只读 |
| `query_backup_summary` | `GET /api/monitor/backup/summary` | `backup:record:list` | 只读 |
| `trigger_backup` | `POST /api/monitor/backup/records` | `backup:record:create` | 可写（需确认） |

约束：

- 工具身份只取自登录态；模型传入的 `userId` / `deptId` / `token` 会被忽略；
- 未登记的工具不会被调用，也无法通过提示词扩大工具集；
- 工具结果去除 `Result` 包装、限制行数与字符数，并屏蔽密码、令牌等字段。

### 12.4 接口

| 方法 | 路径 | 权限 |
|---|---|---|
| POST | `/api/ai/agent/chat/stream` | `ai:agent:use` |
| POST | `/api/ai/agent/runs/{runId}/confirm` | `ai:agent:use` |
| GET | `/api/ai/agent/agents` | `ai:agent:use` |
| GET/POST/PUT/DELETE | `/api/ai/agent/agents/{id}` | `ai:agent:manage` |

流式事件：

| 事件 | 数据 |
|---|---|
| `meta` | `{runId, conversationId, agentId}` |
| `step` | `{seq, tool}` |
| `tool_result` | `{seq, tool, state}` |
| `pending_approval` | `{runId, tool, argsDigest}` |
| `token` | `{delta}` |
| `done` | `{status, usage}` |
| `error` | `{code, message, retryable}` |

### 12.5 写操作确认

1. 模型调用 `trigger_backup` 时，服务**不执行**，而是登记待确认动作，流以 `pending_approval` + `done{status=PENDING_APPROVAL}` 结束。
2. 前端展示确认卡片，用户确认后调用 `/runs/{runId}/confirm`，请求体 `{"approve": true}`。
3. 服务端校验运行归属、有效期、状态与参数摘要后，按**记录中的原始参数**执行，不再解析模型输出。
4. 拒绝、过期或重复确认都不会执行工具。

```bash
TOKEN="<登录返回的 token>"

curl -N http://localhost:8081/api/ai/agent/chat/stream \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
```

## 13. 知识图谱（1.4 / 1.5）

### 13.1 同步与环境变量

知识图谱把 `sys_dept` / `sys_user` / `sys_role` / `sys_menu` 及其关系写入 Neo4j，供智能体回答「谁能访问什么」「跨部门协作路径」这类多跳问题。能力默认关闭，关闭时不建立任何图数据库连接。

**前置条件**

1. 启动图库（带 `graph` profile，默认不随 compose 启动）：

```bash
docker compose --profile graph up -d neo4j
```

2. 在 `.env` 中配置连接与开关：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `NEO4J_PASSWORD` | `iboot123456` | compose 中 neo4j 容器的认证密码 |
| `IBOOT_AI_GRAPH_ENABLED` | `false` | 是否启用图能力 |
| `IBOOT_AI_GRAPH_URI` | `bolt://localhost:7687` | Bolt 连接地址 |
| `IBOOT_AI_GRAPH_USERNAME` | `neo4j` | 图库用户名 |
| `IBOOT_AI_GRAPH_PASSWORD` | 空 | 图库密码，需与 `NEO4J_PASSWORD` 一致 |
| `IBOOT_AI_GRAPH_SYNC_PAGE_SIZE` | `200` | 拉取用户/角色的分页大小 |
| `IBOOT_AI_GRAPH_SYNC_MAX_PAGES` | `50` | 最大翻页数保护 |
| `IBOOT_AI_GRAPH_QUERY_MAX_ROWS` | `50` | 单次查询返回行数上限 |
| `IBOOT_AI_GRAPH_QUERY_TIMEOUT_SECONDS` | `10` | 查询超时秒数 |

3. 以**超级管理员**登录 portal，取得 JWT（调用者必须同时具备 `ai:graph:use` 与 admin 的 `dept:list` / `user:list` / `role:list` / `menu:list`）。

**触发同步**

```bash
curl -X POST http://localhost:8081/api/ai/graph/sync \
  -H "Authorization: Bearer <TOKEN>"
```

响应示例：

```json
{"syncId":"...","syncedAt":"2026-10-28T10:00:00Z","departments":3,"users":12,
 "roles":4,"menus":86,"relations":123,"removed":1}
```

同步规则：

- 使用**调用者自己的登录态**读取 admin，系统不保存服务账号；admin 侧 RBAC 与数据权限原样生效。
- 先取完整快照，再在单个事务内整体替换；失败时旧图保持不变。
- 重复执行幂等：同一快照写入不会产生重复节点；快照中已删除的实体连同关系一起清理。
- 同步为单飞执行，并发请求会返回「已有同步任务进行中」。

**查询状态**

```bash
curl http://localhost:8081/api/ai/graph/status \
  -H "Authorization: Bearer <TOKEN>"
```

返回 `synced`、`syncedAt` 与各类节点数量；从未同步过时 `synced=false`。

> 当前为手动触发同步，定时刷新等待阶段 2 的服务身份（Nacos / mTLS）后再补。

### 13.2 查询模板

系统只提供固定模板，模型只能选择模板并填写参数，**不能生成自由 Cypher**。

| 工具 | 模板 | 跳数 | 参数 | 回答的问题 |
|---|---|---|---|---|
| `query_org_graph` | `search_nodes` | 1 | `keyword`（必填）、`nodeType`（`dept`/`user`/`menu`，可省略） | 名称 → 主键或权限码：部门、用户、菜单 |
| `query_org_graph` | `colleagues` | 2 | `userId`（可省略，默认本人） | 某人的同部门同事 |
| `query_org_graph` | `dept_members` | 2+ | `deptId` | 部门及其所有下级部门的成员 |
| `query_org_graph` | `user_permissions` | 2 | `userId`（可省略，默认本人） | 某人通过角色获得的菜单权限 |
| `query_org_graph` | `perm_holders` | 3 | `permission` | 谁能访问某个功能 |
| `query_dept_path` | `dept_path` | 路径长度 | `fromDeptId`、`toDeptId` | 两个部门之间的组织路径 |

参数缺失或非法时返回 400 与可辨识的错误码，不会执行任何查询。

**名称解析（`search_nodes`）**

模型在只拿到名称（如「研发部」「用户管理」）时，先用 `search_nodes` 解析主键或权限码，再调用上表中的查询模板。

- 匹配规则为名称包含匹配，完全匹配排在前面；`nodeType` 省略时部门、用户、菜单三类都查。
- 部门结果带 `parentName`（上级部门名称），用于区分不同上级下的同名部门；菜单结果带 `permission`（权限码），可直接用于 `perm_holders`。
- 没有权限码的菜单不作为解析结果返回；非超管只能解析到可见部门内的部门与用户，菜单只能经「可见用户 → 角色 → 菜单」暴露。
- 无匹配时返回空结果而非错误，模型应请用户确认名称；重名时返回多个候选，模型应列出候选请用户选择。
- 关键词缺失或只有空白时返回 `invalid_request`。

### 13.3 权限模型

| 控制点 | 规则 |
|---|---|
| 能力入口 | 调用者必须具备 `ai:graph:use`（admin Flyway `V27` 新增，默认仅超管） |
| 数据范围 | 非超管只能看到 `visibleDeptIds` 内的部门与用户；范围取自 admin 的 `/api/auth/scope`，缓存 60 秒 |
| 查询他人权限 | 额外要求 `user:list`；查询本人不受此限 |
| 失败关闭 | 范围服务不可用时直接拒绝查询并返回 503，**不会**回落到未过滤的全量结果 |
| 结果规模 | 单次最多返回 `IBOOT_AI_GRAPH_QUERY_MAX_ROWS`（默认 50）行，超出即截断 |

越权排除的验证方式（与 1.2 红队用例同一标准）：

- 自动化：`GraphQueryRepositoryTest#hidesDepartmentsOutsideVisibleScope` 断言可见范围外的部门成员、权限持有人与跨部门路径全部返回空；`GraphScopeResolverTest#failsClosedWhenScopeUnavailable` 断言范围服务不可用即拒绝。
- 手工：用一个可见范围仅含「市场部」的账号与智能体对话，提问「研发部有哪些人」。回答应说明没有可见数据，而不是列出研发部成员。

### 13.4 智能体工具清单

| 工具 | 只读 | 所需权限 | 参数 | 说明 |
|---|---|---|---|---|
| `query_org_graph` | 是 | `ai:graph:use` | `template`、`keyword`、`nodeType`、`userId`、`deptId`、`permission` | 组织与 RBAC 关系查询，按 §13.2 的模板取值 |
| `query_dept_path` | 是 | `ai:graph:use` | `fromDeptId`、`toDeptId` | 两个部门之间的最短组织路径 |

两个工具都是只读的，**不会**触发两段式确认；模型传入的 `userId` 只作为查询目标，调用者身份始终取自登录态。

**把工具加入智能体白名单**

工具必须在智能体的 `toolAllowlist` 中，模型才能看到并调用。两种方式：

1. 在「智能体管理」页面编辑目标智能体，把 `query_org_graph` / `query_dept_path` 加入工具白名单并保存。
2. 通过接口更新：

```bash
curl -X PUT http://localhost:8081/api/ai/agent/agents/<AGENT_ID> \
  -H "Authorization: Bearer <TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"name":"组织助手","description":"查询组织关系","systemPrompt":"你可以查询组织架构与权限关系。",
       "toolAllowlist":["query_org_graph","query_dept_path"],"enabled":true}'
```

> 白名单在每次运行开始时读取；修改不影响进行中的运行。关闭图能力时两个工具不会注册，
> 白名单中的名字会被忽略，模型看不到它们。

| 指标 | 标签 | 含义 |

**错误码**

| code | HTTP | 含义 | 处理 |
|---|---|---|---|
| `graph_disabled` | 503 | 图能力未启用 | 设置 `IBOOT_AI_GRAPH_ENABLED=true` 并重启 |
| `graph_unavailable` | 503 | 图库或权限范围不可用 | 检查 Neo4j 容器与 admin `/api/auth/scope` |
| `graph_access_denied` | 403 | 缺少 `ai:graph:use` 或查询他人权限缺 `user:list` | 在 admin 授权后重新登录 |
| `graph_sync_failed` | 502 | 同步失败（下游错误、权限不足、超过翻页数） | 按返回消息补齐权限或调大 `IBOOT_AI_GRAPH_SYNC_MAX_PAGES` |
| `invalid_request` | 400 | 模板参数缺失或非法 | 按 §13.2 补齐参数 |

**常见问题**

| 现象 | 原因 | 处理 |
|---|---|---|
| 同步返回 502 且提示缺少权限 | 调用者不是超管或缺少 `dept:list` 等权限 | 使用超级管理员账号同步 |
| 同步返回 502 提示超过翻页数 | 组织规模超过 `page-size × max-pages` | 调大 `IBOOT_AI_GRAPH_SYNC_MAX_PAGES` |
| 状态显示从未同步 | 尚未触发同步 | 调用 `POST /api/ai/graph/sync` |
| 智能体看不到图工具 | 图能力关闭，或工具不在智能体白名单 | 开启图能力并更新 `toolAllowlist`（§13.4） |
| 查询结果为空 | 数据不在调用者可见部门内 | 属预期行为；确认 `visibleDeptIds` 后再排查 |
| 回答"请确认部门/功能名称" | 名称未匹配到任何可见节点 | 属预期行为；核对名称是否与 admin 一致，或先执行一次同步 |
| 解析列出多个同名部门 | 不同上级下存在同名部门 | 属预期行为；按上级选择后重新提问 |
| 名称解析报"缺少查询关键词" | `search_nodes` 未传 `keyword` | 检查智能体是否传参；属模型调用问题而非权限问题 |
| 启动报连接失败 | Neo4j 未启动或密码不一致 | 检查 `graph` profile 与 `IBOOT_AI_GRAPH_PASSWORD` |
