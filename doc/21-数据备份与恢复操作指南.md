# 数据备份与恢复操作指南

> 适用版本：iBoot 阶段 0.2（Flyway V22 起）
>
> 本文覆盖数据库逻辑备份的启用、定时/手动执行、加密产物存储、恢复演练与排障。

---

## 1. 功能边界

| 能力 | 说明 |
|---|---|
| 全量逻辑备份 | 使用 `mysqldump` 导出一致性快照，AES-256-GCM 加密后写入当前文件存储 |
| 定时/手动触发 | Quartz 任务 `backupTask.run`（默认每天 02:00）；管理端“数据备份”页面可立即触发 |
| 备份元数据 | `db_backup_record` 记录状态、大小、校验和、存储路径与逐表行数快照 |
| 恢复演练 | 只还原到固定演练库 `iboot_restore_drill`，逐表比对行数，结果写入 `db_restore_record` |
| 明确不做 | binlog 增量、时间点恢复、自动过期删除、RDS 原生备份、备份失败通知 |

> **恢复演练不会覆盖业务库。** 服务层强制目标库必须以 `iboot_restore_` 开头且不得等于业务库名，接口不接受客户端传入目标库名。

---

## 2. 前置条件

1. MySQL 容器已启动：`docker compose -f docker/docker-compose.yml up -d mysql`
2. MinIO 已启动（若希望产物落对象存储）：`docker compose -f docker/docker-compose.yml up -d minio minio-init`
3. 宿主机可执行 `docker` 命令；应用进程与 Docker CLI 使用同一用户
4. 已生成 32 字节主密钥并写入 `.env`（见下一节）

本地不需要安装 `mysqldump`/`mysql` 客户端：默认命令通过 `docker exec` 进入 `iboot-mysql` 容器执行，容器内 `mysqldump` 版本为 8.0.45，与数据库一致。

## 3. 启用步骤

### 3.1 生成并保存主密钥

```bash
cd /home/lam/workspace/iboot

KEY="$(openssl rand -base64 32)"

printf '\n# ============================================================\n# iBoot 0.2 数据备份与恢复 — 本地环境变量\n# ============================================================\n# AES-256-GCM 主密钥（Base64 编码的 32 字节随机值）\n# 生成：openssl rand -base64 32\n# 丢失后已加密的备份无法恢复，请同时保存在密码管理器中\nIBOOT_BACKUP_ENCRYPTION_KEY="%s"\n' "$KEY" >> .env

echo "已写入 .env，请立即保存到密码管理器：$KEY"
```

校验（必须输出 `32`）：

```bash
set -a; source .env; set +a
printf '%s' "$IBOOT_BACKUP_ENCRYPTION_KEY" | base64 -d | wc -c
```

`.env` 已被 `.gitignore` 忽略；`.env.example` 只保留空占位符，禁止写入真实密钥。

### 3.2 启用备份

在 `.env` 中设置：

```dotenv
IBOOT_BACKUP_ENABLED=true
```

### 3.3 选择备份产物的存储介质（可选）

默认 `sys.file.storageType=local`，产物落本地目录；若希望落 MinIO：

```sql
UPDATE sys_config SET config_value = 'minio' WHERE config_key = 'sys.file.storageType';
```

该配置在启动期读取，修改后需要重启应用。对象位置为：

```text
{当前存储桶}/backup/{数据库名}/{yyyy}/{MM}/{dd}/{备份编号}.sql.enc
```

MinIO 控制台：<http://localhost:9001>，默认账号 `minioadmin/minioadmin`。

### 3.4 启动应用

```bash
cd /home/lam/workspace/iboot
set -a; source .env; set +a
mvn -s /home/lam/repo/settings.xml -pl iboot-admin spring-boot:run
```

启动时若 `IBOOT_BACKUP_ENABLED=true` 但密钥缺失、无法解码或不是 32 字节，应用会直接启动失败并提示 `IBOOT_BACKUP_ENCRYPTION_KEY`。

## 4. 配置项

| 配置 | 默认值 | 说明 |
|---|---|---|
| `iboot.backup.enabled` | `false` | 功能总开关 |
| `iboot.backup.encryption-key` | 空 | 主密钥，仅从 `IBOOT_BACKUP_ENCRYPTION_KEY` 注入 |
| `iboot.backup.database.host/port/name` | `localhost/3306/iboot_admin` | 备份源库连接（JDBC 与命令共用，除非单独覆盖） |
| `iboot.backup.database.username/password` | `root/root` | 备份账号；密码只经 `MYSQL_PWD` 传给子进程 |
| `iboot.backup.command.dump-prefix` | `docker exec -i -e MYSQL_PWD iboot-mysql mysqldump` | 导出命令前缀（列表形式，无 shell 拼接） |
| `iboot.backup.command.restore-prefix` | `docker exec -i -e MYSQL_PWD iboot-mysql mysql` | 还原命令前缀 |
| `iboot.backup.command.host/port` | 空 | 命令视角的数据库地址；为空时沿用 `database.*` |
| `iboot.backup.restore.schema` | `iboot_restore_drill` | 固定演练库名 |
| `iboot.backup.restore.prefix` | `iboot_restore_` | 允许的演练库前缀 |
| `iboot.backup.stale-running-minutes` | `30` | 运行中记录超时重置阈值 |

导出命令固定带上：

```text
--single-transaction --quick --default-character-set=utf8mb4
--set-gtid-purged=OFF --no-tablespaces
```

不使用 `--databases`，因此同一份 dump 可以还原到不同库名。

## 5. 执行备份与验证

### 5.1 手动触发

管理端：**系统运维 → 数据备份 → 立即备份**。

同一时刻只允许一个备份运行；重复触发会返回“已有备份正在执行”。

### 5.2 定时触发

Flyway V21 已种入任务：

```sql
SELECT job_name, invoke_target, cron_expression, concurrent, status
FROM sys_job
WHERE invoke_target = 'backupTask.run';
```

cron 可在 **系统运维 → 定时任务管理** 中修改，默认每天 02:00。`concurrent=0` 禁止任务自身并发。

### 5.3 检查结果

```sql
SELECT id, backup_no, trigger_type, status, storage_type, storage_path,
       ciphertext_size, plaintext_size, checksum_sha256, duration_ms, error_message
FROM db_backup_record
ORDER BY id DESC
LIMIT 5;
```

成功的记录必须满足：`status='SUCCESS'`、`storage_path` 非空、`checksum_sha256` 为 64 位、错误信息为空。

MinIO 中核对对象：

```bash
docker exec -it iboot-minio sh -c \
  'mc alias set local http://localhost:9000 minioadmin minioadmin >/dev/null && mc ls -r local/iboot-files/backup/'
```

## 6. 恢复演练

### 6.1 触发

管理端：**数据备份 → 备份记录 → 恢复演练**（仅成功记录可操作）。

演练目标固定为 `iboot_restore_drill`。每次演练会先删除再重建该库，演练结束后保留供人工查看；下一次演练时重建，占用有界。

### 6.2 校验逻辑

1. 从存储读取加密对象；
2. 解密并校验 GCM 认证标签；
3. 计算明文 SHA-256，与 `db_backup_record.checksum_sha256` 比对；
4. 校验全部通过后才重建演练库并执行还原；
5. 逐表比对演练库行数与备份时的 `table_stats_json`；
6. 全部一致为 `SUCCESS`；存在差异为 `MISMATCH` 并列出差异表；执行异常为 `FAILED`。

密文损坏、校验和不一致时，系统会在任何 DDL 之前失败，不会创建或清空演练库。

### 6.3 查看结果

```sql
SELECT id, backup_id, target_schema, status, table_count, duration_ms, error_message
FROM db_restore_record
ORDER BY id DESC
LIMIT 5;

-- 演练库是否存在
SELECT schema_name FROM information_schema.schemata WHERE schema_name = 'iboot_restore_drill';
```

管理端演练详情会展示差异表、期望行数与实际行数。

### 6.4 行数不一致怎么办

`MISMATCH` 不是成功。常见原因：

- 备份与演练之间业务库有写入，但比对的基线是**备份时的快照**，正常写入不应影响演练结果；若出现差异，优先检查备份时快照与 dump 的时间差；
- 备份期间存在大事务或 DDL；
- 演练库中残留了上一次的额外对象（本实现每次重建，理论上不会）。

处理：选择业务低峰重新执行一次备份，然后立即演练。不要手工把 `MISMATCH` 改成 `SUCCESS`。

### 6.5 演练库清理

```sql
DROP DATABASE IF EXISTS iboot_restore_drill;
```

该操作只影响演练库，不影响业务库。

## 7. 密钥与安全

- 备份对象包含 `sys_user` 密码哈希与 `sys_config` 中的 MinIO 密钥，**必须加密存储**。
- 主密钥只存在于环境变量和你的密码管理器中；数据库中只保存算法标识。
- **密钥丢失等于备份永久不可用**。0.2 不支持密钥轮换。
- 错误信息写入数据库前会替换数据库密码与主密钥，并截断到 1000 字符。
- 接口不返回数据库密码或主密钥；存储路径仅对有备份查看权限的用户可见。

## 8. 常见问题

### Q1：提示“无法启动命令: docker”

应用进程找不到 `docker`。确认：

```bash
docker version
```

并从与当前 shell 相同的用户/环境启动应用（IDE 启动时检查 PATH）。

### Q2：提示 Access denied

`docker exec -e MYSQL_PWD` 从客户端环境读取密码。确认应用进程环境中存在 `MYSQL_PWD`（由 `iboot.backup.database.password` 注入），或改用 `--defaults-extra-file` 方式。

### Q3：mysqldump 版本不匹配

本项目默认使用容器内客户端，版本与 `mysql:8.0.45` 一致。若改为宿主机客户端，必须自行保证主版本为 8.0.45。

### Q4：Testcontainers 报无法拉取 `testcontainers/ryuk`

本机只缓存了 `0.12.0`，运行容器测试时指定：

```bash
TESTCONTAINERS_RYUK_CONTAINER_IMAGE=testcontainers/ryuk:0.12.0 \
  mvn -s /home/lam/repo/settings.xml -pl iboot-admin test
```

### Q5：演练失败提示无权建库

本地 root 账号具备权限；云上 RDS 账号可能没有 `CREATE DATABASE`。阶段 3 需由 IaC 预建演练库或授予专用账号权限。

### Q6：开发模式下立即执行任务报 ClassCastException

Spring Boot DevTools 的重启类加载器与 Quartz 工作线程类加载器不一致时，`Job` 对象跨类加载器转换会失败；现有其他定时任务同样受影响，与备份功能无关。验证定时任务时关闭 DevTools restart：

```bash
mvn -s /home/lam/repo/settings.xml -pl iboot-admin spring-boot:run \
  -Dspring-boot.run.jvmArguments="-Dspring.devtools.restart.enabled=false"
```

或使用打包后的 jar 运行。

## 9. 回滚

1. 将 `IBOOT_BACKUP_ENABLED` 设为 `false` 并重启应用；
2. 或在任务管理页暂停 `backupTask.run`；
3. 已产生的备份记录与对象保留，不删除；
4. Flyway V21/V22 只新增表、种子数据与菜单归属，不回滚表结构。

---

## 10. 上云替换点

| 本地实现 | 云端演进 |
|---|---|
| `docker exec` 调用容器内 `mysqldump` | 镜像内自带 mysql-client，或新增调用 RDS 备份 API 的 `BackupExecutor` 实现 |
| MinIO 存储 | 既有 `FileStorageStrategy` 切换为 `oss`，备份业务代码不变 |
| 环境变量密钥 | ACK Secret / KMS |
| 单实例进程内锁 | Quartz 集群 + 数据库级锁 |
| 逻辑备份 | RDS 自动备份仍是云端主路径；本能力承载可移植导出与恢复演练验证 |
