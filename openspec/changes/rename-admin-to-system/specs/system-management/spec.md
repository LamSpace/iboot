# Spec Delta

## Purpose

定义系统域作为独立可部署单元的所有权与对外契约：谁拥有用户、角色、菜单、部门、岗位、字典与参数，谁提供数据权限范围，其余服务以何种方式、在何种失败语义下消费这些数据。

## ADDED Requirements

### Requirement: 系统域作为独立可部署单元

系统域 SHALL 由一个独立模块、独立进程承载，拥有用户、角色、菜单、部门、岗位、字典类型、字典数据、参数配置八类实体及其关联表，并通过网关对外提供其全部管理端点。

- 该服务 MUST 能在不启动其他业务服务的情况下独立完成启动与健康检查。
- 该服务 MUST 是上述八类实体及其关联关系的权威写入方；其他服务 MUST NOT 创建或修改这些表的结构。
- 写入侧的例外 MUST 逐条登记在项目文档中，且 MUST 限定为单一用途的最小写集。当前登记的例外只有两项：认证服务写入 `sys_user` 的注册记录与最后登录信息；各服务经内核写入监控服务拥有的审计表（后者由 `ops-monitoring` 定义，不属于本能力）。
- 除登记例外外，其他服务 MUST NOT 写入系统域的表。
- 该服务的对外端点集合、路径与方法 MUST 与改名之前逐条一致；本约束的目的是固定归属，而非改变行为。
- 该服务的启停 SHALL NOT 影响文件、消息、调度、审批、监控与 AI 各域的只读查询可用性。
- 该服务 MUST 在注册中心注册自身并参与分布式追踪。

#### Scenario: 独立启动

- **WHEN** 只启动中间件与系统服务
- **THEN** `/actuator/health` 返回 UP
- **AND** 该服务已在注册中心可见

#### Scenario: 端点集合不漂移

- **WHEN** 对比改名前后系统域的接口基线
- **THEN** 全部 57 条路径在目标服务中存在，方法与响应结构不变
- **AND** 路径守恒检查通过，不出现未登记的路径缺口或凭空出现的路径

#### Scenario: 写入例外不扩散

- **WHEN** 检查除系统服务外任何服务对系统域表的写入语句
- **THEN** 命中的语句只能属于已登记的例外，且只写该例外声明的列

#### Scenario: 前端无感

- **WHEN** 前端经网关依次完成登录、修改用户、上传文件、接收站内消息
- **THEN** 全部操作成功
- **AND** 前端构建产物与配置文件无需任何改动

### Requirement: 数据权限范围的唯一提供方

数据权限范围（调用者可见的部门集合、角色集合与是否超级管理员）SHALL 由系统域计算并对外提供，其余服务 MUST 通过该接口获取，不得自行推导。

- 该接口 MUST 以调用者自身的登录态鉴权，返回结果 MUST 与系统域内部数据权限拦截器使用的口径一致。
- 消费方 MUST 在使用前本地缓存该结果，缓存有效期 MUST 可配置。
- 消费方 MUST 失败关闭：无法取得权限范围时，带数据范围要求的查询 MUST 返回明确错误，不得退化为「不做过滤」或「返回空列表并宣称为完整结果」。
- 消费方 MUST 在服务恢复后自动恢复，不得要求重启。

#### Scenario: 权限范围与本地拦截器同源

- **WHEN** 同一调用者分别访问系统域自身的数据权限查询与其他服务的数据权限查询
- **THEN** 两者可见的记录集合一致

#### Scenario: 权限服务不可用时失败关闭

- **WHEN** 系统服务不可达且调用方的本地缓存已过期
- **THEN** 带数据范围要求的查询返回明确错误
- **AND** 不返回任何未经过滤的数据

#### Scenario: 缓存窗口内仍可用

- **WHEN** 系统服务在缓存有效期内不可达
- **THEN** 消费方仍以缓存结果正常响应
- **AND** 缓存过期后才转为失败关闭

### Requirement: 系统域数据的跨 schema 只读契约

其余服务 SHALL 以跨 schema 只读的方式消费系统域数据，该方式 MUST 被作为长期模式接受，而不是待消除的临时债务；同时 MUST 把消费面收敛为显式、有测试锁定的契约。

- 每个消费方 MUST 只读取其契约中登记的表与列，MUST NOT 依赖未登记的表或列。
- 消费方 MUST 以只读方式访问，不得写入系统域的任何表。
- 契约 MUST 在项目文档中逐服务登记表名、列名与用途，并在消费方以测试锁定列名与语义。
- 系统域 MUST 把被消费的表列视为对外接口：删除或重命名列 MUST 视为破坏性变更，需要与消费方同批发布。
- 消费方在系统域不可用时的行为 MUST 是明确错误，不得静默返回空集合、默认值或降级为不过滤。

#### Scenario: 契约外访问被发现

- **WHEN** 某消费方新增对未登记表或列的读取
- **THEN** 该消费方的契约测试失败并指出未登记的字段

#### Scenario: 消费方只读

- **WHEN** 检查任一消费方的数据库访问代码
- **THEN** 对系统域表的语句只有查询，没有写入或结构变更

#### Scenario: 系统域不可用时消费方给出明确错误

- **WHEN** 系统服务停止且某消费方需要读取用户信息
- **THEN** 该消费方返回可辨识的业务错误
- **AND** 不返回空列表并当作正常结果

### Requirement: 服务身份与寻址

系统服务的注册中心身份 SHALL 与其模块名一致，依赖方 MUST 以服务名寻址，不得硬编码宿主端口。

- 网关 MUST 以专用路由把系统域的兜底路径转发到该服务，路由优先级 MUST 低于所有更具体的业务路由。
- 依赖方配置 MUST 提供以服务名寻址的默认值，并允许通过配置覆盖。
- 本次改名 MUST NOT 改变对外端口，以使按端口寻址的既有配置继续有效。

#### Scenario: 服务名寻址生效

- **WHEN** 依赖方通过注册中心地址调用数据权限范围接口
- **THEN** 请求到达系统服务并成功返回

#### Scenario: 兜底路由不抢业务路径

- **WHEN** 请求路径属于文件、消息、调度、审批、监控或认证域
- **THEN** 该请求由对应业务服务处理，不落到系统服务

#### Scenario: 端口不变

- **WHEN** 按既有端口直接访问系统服务的健康检查端点
- **THEN** 返回 UP，无需修改任何按端口配置的调用方

### Requirement: 聚合视图对日志数据的只读消费

仪表盘与统计视图 SHALL 留在系统服务内，并跨 schema 只读监控服务拥有的登录日志与操作日志表；该方式 MUST 被作为长期模式接受。

- 该消费 MUST 只读取聚合所需的表与列，MUST NOT 写入审计表。
- 该消费 MUST NOT 改为对监控服务的同步远程调用，除非同时证明仪表盘在监控服务不可用时仍能返回可用结果。
- 审计表结构变更 MUST 视为破坏性变更，与消费方同批发布。

#### Scenario: 监控服务不可用时仪表盘仍可用

- **WHEN** 监控服务停止运行
- **THEN** 仪表盘与统计接口仍返回成功响应
- **AND** 日志统计数字取自最近一次可读的数据

#### Scenario: 聚合视图不影响审计写入

- **WHEN** 仪表盘与统计接口被频繁调用
- **THEN** 审计表的写入路径不受影响
- **AND** 审计记录不因读取而减少或改变
