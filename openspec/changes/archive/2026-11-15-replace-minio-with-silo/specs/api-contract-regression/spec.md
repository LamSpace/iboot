# Spec Delta

## MODIFIED Requirements

### Requirement: 契约零漂移判定

服务拆分与改造 MUST NOT 改变任何既有对外接口的路径、方法、必填参数与响应结构，除非该差异已按本要求显式登记。

- 改造后的导出结果与基线比较 MUST 完全一致；不一致时检查 MUST 失败并指出具体差异。
- 允许的差异 MUST 显式登记；每条登记 MUST 说明理由，破坏性重命名 MUST 同步更新接口基线。
- 检查 MUST 在构建或持续集成中自动执行，不得依赖人工发起。

#### Scenario: 无变化时检查通过

- **WHEN** 改造未改变任何接口，执行契约检查
- **THEN** 检查通过

#### Scenario: 路径变化导致失败

- **WHEN** 某接口的路径或方法与基线不一致，且该差异未登记
- **THEN** 检查失败并指出该接口的差异

#### Scenario: 未登记的差异导致失败

- **WHEN** 出现与基线不同的差异，且未登记为允许项
- **THEN** 检查失败

#### Scenario: 已登记的新增接口不导致失败

- **WHEN** 新增了一个接口并已显式登记
- **THEN** 检查通过，且新增接口出现在新的基线中

#### Scenario: 已登记的破坏性重命名不导致失败

- **WHEN** 一个既有接口被重命名，该差异已显式登记并同步更新接口基线
- **THEN** 检查通过，且新路径出现在新的基线中
- **AND** 登记内容说明重命名理由与旧路径
