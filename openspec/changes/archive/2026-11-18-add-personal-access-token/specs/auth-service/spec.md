# Spec Delta

## MODIFIED Requirements

### Requirement: 认证写入的过渡期边界

过渡期内认证服务 SHALL 直连共享数据库完成登录、注册与个人访问令牌所需的数据读写：用户与角色数据来自系统域拥有的表，登录日志写入监控服务拥有的审计表，令牌元数据写入系统域登记的表；这些访问 MUST 被登记为临时状态，并附退出条件。

- 允许的读操作 MUST 仅限登录、注册与 PAT 签发所需的用户、角色、菜单、参数与令牌元数据。
- 允许的写操作 MUST 仅限：更新 `sys_user` 的最后登录信息、注册时插入 `sys_user`、插入登录日志、签发与撤销时写入 `sys_user_pat` 的令牌元数据。
- 登录日志 MUST 写入监控服务拥有的审计表，MUST NOT 另建同名表。
- 除上述登记例外，认证服务 MUST NOT 修改其他服务的业务表。
- 登录日志写入失败 MUST NOT 导致登录失败。
- PAT 元数据写入失败 MUST 导致签发或撤销失败，避免出现无法撤销的令牌。

#### Scenario: 登录成功更新最后登录信息

- **WHEN** 用户登录成功
- **THEN** 对应用户的最后登录 IP 与时间被更新
- **AND** 生成一条成功登录日志

#### Scenario: 登录日志落入审计表

- **WHEN** 一次登录成功或失败
- **THEN** 登录日志出现在监控服务拥有的审计表中
- **AND** 该记录可被日志查询与导出检索到

#### Scenario: 登录日志写入失败不影响登录

- **WHEN** 登录日志写入过程中发生异常
- **THEN** 登录仍然成功返回令牌

#### Scenario: 账号锁定语义不变

- **WHEN** 同一用户连续失败达到配置阈值
- **THEN** 返回与拆分前一致的锁定提示
- **AND** 锁定期间即使密码正确也拒绝登录

#### Scenario: PAT 元数据写入受限

- **WHEN** 认证服务签发或撤销个人访问令牌
- **THEN** 只写入 `sys_user_pat` 中该用户自己的令牌元数据
- **AND** 不改动系统域的其他表

### Requirement: 令牌自包含与撤销名单

资源服务 SHALL 仅凭令牌签名与声明完成鉴权，撤销名单用于使失效即时生效。

- 资源服务 MUST 通过 JWK 验签并读取令牌声明建立授权上下文。
- 资源服务 MUST NOT 依赖认证服务在线才能完成鉴权。
- 认证服务 MUST 维护撤销名单，登出与强制下线后下一次请求 MUST 被拒绝。
- 个人访问令牌 MUST 使用独立的撤销命名空间；撤销、过期与用户停用或删除后下一次请求 MUST 被拒绝。
- 撤销与在线名单 MUST 保存在共享存储中，沿用拆分前的键前缀，使既有运维与管理功能平滑过渡。

#### Scenario: 认证服务停止时已签发令牌仍可用

- **WHEN** 认证服务停止运行，客户端使用此前签发的令牌访问业务服务
- **THEN** 业务服务返回正常的业务响应

#### Scenario: 登出使令牌立即失效

- **WHEN** 用户登出，随后用同一令牌访问任一业务服务
- **THEN** 请求被拒绝

#### Scenario: 强制下线使令牌立即失效

- **WHEN** 管理员对某用户执行强制下线，该用户随后发起请求
- **THEN** 请求被拒绝

#### Scenario: PAT 撤销进入独立命名空间

- **WHEN** 个人访问令牌被撤销
- **THEN** 其撤销记录从 PAT 专用命名空间移除
- **AND** 令牌在下一次请求时被拒绝

### Requirement: 在线会话对管理员可见可控

管理员 SHALL 能查看当前在线会话并对指定用户强制下线。

- 在线列表 MUST 反映当前有效的会话，而不只是登录历史。
- 强制下线 MUST 立即生效于该用户的全部令牌。
- 在线列表与强制下线的判定结果 MUST 与拆分前一致。
- **过渡期例外**：`client_id=iboot-cli` 的会话 MUST NOT 写入 `online_token:<userId>`，因此 MUST NOT 出现在在线列表，MUST NOT 被按用户的强制下线覆盖；此例外 MUST 在 `add-multi-client-sessions` 落地后移除。
- **PAT 例外**：个人访问令牌 MUST NOT 出现在在线列表，也 MUST NOT 被会话级强制下线覆盖；其撤销 MUST 通过 PAT 管理接口完成，用户停用或删除时同步失效。

#### Scenario: 在线列表可见

- **WHEN** 管理员打开在线用户页面
- **THEN** 能看到当前在线用户及其登录时间、IP 与浏览器信息

#### Scenario: 强制下线

- **WHEN** 管理员对某在线用户执行强制下线
- **THEN** 该用户在该列表中的记录消失
- **AND** 该用户的后续请求被拒绝

#### Scenario: CLI 会话不参与在线名单（过渡期）

- **WHEN** 用户通过 `iboot-cli` 完成授权码登录
- **THEN** 该会话不出现在在线列表
- **AND** 管理员对该用户执行强制下线时，该 CLI 会话不被撤销
- **AND** 该例外在 `add-multi-client-sessions` 落地后失效

#### Scenario: PAT 不参与在线名单

- **WHEN** 管理员打开在线用户页面
- **THEN** 列表不包含 PAT 会话
- **AND** 会话级强制下线不影响 PAT
- **AND** PAT 只能通过令牌管理接口或用户停用、删除撤销
