# Spec Delta

## Purpose

提供一套可选、可整体摘除的第二 APM 观测栈，使同一批服务、同一批流量能同时被既有 Tempo 与 SkyWalking 观测，从而比较 agent 零侵入埋点与 SDK 埋点的实际代价与能力，而不改变主追踪链路。

## ADDED Requirements

### Requirement: 辅助 APM 栈按需启停且可整体摘除

辅助观测栈 SHALL 以独立编排 profile 提供，包含存储、OAP 与查询界面三个组件，并且 MUST NOT 成为任何业务服务的启动依赖。

- 三个组件 MUST 只在显式启用该 profile 时启动，默认不占用端口与内存。
- 任一组件不可用 MUST NOT 阻止业务服务启动或请求处理。
- 停止或删除整套辅助栈 MUST NOT 影响业务服务、既有追踪链路或任何持久化业务数据。
- 辅助栈的存储 MUST 与业务数据、既有 Tempo 数据相互隔离，删除时不得波及其他卷。

#### Scenario: 默认不启动

- **WHEN** 按常规方式启动本地开发环境且未启用辅助 profile
- **THEN** 辅助栈的三个容器均不运行
- **AND** 业务服务启动耗时与内存占用与实验前一致

#### Scenario: 整体摘除不影响业务

- **WHEN** 实验结束后停止并删除辅助栈的全部容器与卷
- **THEN** 业务服务继续正常处理请求
- **AND** 既有 Tempo 链路仍可完整查询

#### Scenario: 辅助栈故障不阻塞启动

- **WHEN** 辅助栈未启动或启动失败
- **THEN** 九个业务服务仍能启动并通过健康检查

### Requirement: Agent 以零侵入方式接入服务

辅助观测 SHALL 通过 JVM 启动参数挂载 Java Agent 实现，MUST NOT 要求修改业务代码、业务依赖或既有追踪配置。

- 九个业务服务的观测 MUST 由同一个 Agent 发行包提供，且该发行包版本 MUST 支持当前 Boot 4 / Spring Framework 7 运行时。
- Agent 注入 MUST 由显式开关控制，开关默认关闭；关闭时服务启动命令、依赖与行为 MUST 与实验前完全一致。
- Agent 的接入 MUST NOT 改变服务现有的 OTLP 导出地址、采样设置或响应头行为。

#### Scenario: 开关打开后服务出现在辅助后端

- **WHEN** 以 Agent 开关启动任一业务服务并产生一次请求
- **THEN** 该服务出现在辅助后端的服务列表中
- **AND** 该请求产生对应的链路数据

#### Scenario: 开关关闭时行为不变

- **WHEN** 以默认开关启动任一业务服务
- **THEN** 启动命令中不含 Agent 参数
- **AND** 服务不会尝试连接辅助后端
- **AND** 既有 Tempo 链路照常产生

### Requirement: 同一请求在双后端均可还原

一次经网关进入的请求 SHALL 能在辅助后端与既有 Tempo 中分别还原为完整调用链，且两条链都能对应到同一次请求。

- 辅助后端中的链路 MUST 包含该请求经过的全部业务服务及其调用次序。
- 两条链 MUST 都能定位到具体服务与接口，并标明各段耗时。
- 对应同一次请求的判定方法 MUST 可重复执行，不得依赖人工猜测时间窗口。
- 任一侧的链路缺失或不完整时，验收 MUST 明确失败并指出缺失的服务。

#### Scenario: 双后端链路一致

- **WHEN** 通过网关发起一次跨服务请求
- **THEN** Tempo 与辅助后端都能查到包含全部参与服务的链路
- **AND** 两条链能通过可重复的方法判定为同一次请求

#### Scenario: 链路不完整时验收失败

- **WHEN** 辅助后端缺少某个参与服务的链路段
- **THEN** 验收脚本以非零状态退出
- **AND** 输出中指明缺失的服务

### Requirement: 实验不改变主追踪契约

辅助观测 SHALL 与既有追踪链路并存，MUST NOT 替换 Tempo 或改变 `distributed-tracing` 已定义的任何行为。

- 既有 OTLP 导出、采样比例与网关 `X-Trace-Id` 行为 MUST 保持不变。
- 辅助后端停止 MUST NOT 导致业务请求失败、变慢或丢失 Tempo 链路。
- 实验结论 MUST 只作为选型依据，不得自动触发替换 Tempo 的改动。

#### Scenario: 停辅助后端不影响 Tempo

- **WHEN** 辅助栈全部停止后发起一次请求
- **THEN** 业务请求正常返回
- **AND** Tempo 中仍能查到完整链路

#### Scenario: 既有验收脚本继续通过

- **WHEN** 在辅助栈运行时执行原有的链路验收脚本
- **THEN** 脚本行为与结果与实验前一致

### Requirement: 实验产出可复核的选型结论

实验 SHALL 记录 Agent 对启动时间、常驻内存与吞吐的实际影响，并产出一页选型结论。

- 度量 MUST 说明测量方法、样本与对照组，使他人可以复现。
- 结论 MUST 分别说明 agent 埋点与 SDK 埋点适合的场景及各自代价。
- 结论 MUST 写入项目文档，并在路线图中登记实验状态。

#### Scenario: 度量可复现

- **WHEN** 按文档步骤重新执行度量
- **THEN** 能得到同一量级的启动时间、内存与吞吐数据
- **AND** 文档说明了对照组与样本数量

#### Scenario: 结论落地

- **WHEN** 实验完成
- **THEN** 项目文档中存在一页选型结论
- **AND** 路线图记录实验完成状态与辅助栈的去留

### Requirement: 镜像与版本来源可复现

辅助栈镜像 SHALL 从项目约定的镜像站获取并固定版本，MUST NOT 依赖 Docker Hub 直连。

- OAP、查询界面与存储的版本 MUST 相互兼容；存储的 server API 版本 MUST 与 OAP 要求精确匹配。
- 镜像拉取 MUST 可通过项目现有拉取脚本重复执行，重复执行 MUST NOT 失败。
- 本地缺失镜像时，MUST 能按文档从约定镜像站重新获取，并还原到编排引用的标签。

#### Scenario: 干净环境重建辅助栈

- **WHEN** 在未缓存辅助栈镜像的机器上执行项目镜像拉取脚本
- **THEN** 三个镜像均从约定镜像站获取成功
- **AND** 编排可直接使用固定标签启动
- **AND** 重复执行脚本不报错
