# Spec Delta

## MODIFIED Requirements

### Requirement: 服务只连接数据库，不改变结构

服务进程 SHALL 只使用已经建好的结构，MUST NOT 在启动时执行建表或改表。

- 服务进程 MUST NOT 执行迁移，也 MUST NOT 因为缺少表而自行建表。
- 编排部署 MUST 在服务启动前等待迁移执行者以 0 退出；迁移执行者失败时，依赖其结果的服务的 MUST NOT 启动。
- 脱离编排单独启动服务时，若表不存在，服务 MUST 以明确错误暴露「表不存在」。
- 服务 MUST NOT 打包迁移脚本，MUST NOT 以任何方式创建或修改表结构。
- 服务与迁移执行者 MUST 使用同一个数据库连接信息，避免出现「迁移到 A 库、服务连 B 库」。

#### Scenario: 编排启动按顺序完成
- **WHEN** 编排器先启动迁移执行者并等待其成功退出
- **THEN** 迁移执行者返回 0
- **AND** 服务随后启动并使用已建好的结构

#### Scenario: 迁移失败阻断服务启动
- **WHEN** 迁移执行者以非零退出
- **THEN** 编排器不启动依赖它的服务
- **AND** 失败原因可从迁移执行者日志定位

#### Scenario: 服务不触发迁移
- **WHEN** 服务在已初始化的数据库上启动
- **THEN** 启动过程中不产生任何 DDL 语句

#### Scenario: 未初始化时错误明确
- **WHEN** 服务在空数据库上启动并收到请求
- **THEN** 返回明确错误，日志指出缺少表
- **AND** 服务不会自行建表
