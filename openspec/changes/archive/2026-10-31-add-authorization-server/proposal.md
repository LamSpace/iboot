# Proposal

## Why

`iboot-auth` 目前只完成了物理拆分，登录协议仍是「用户名密码换 JWT + 共享 Redis 会话」：资源服务器把令牌原文当作 Redis key 取会话，权限从会话 Map 读，令牌本身不承载任何授权信息。这带来三个能力缺口——无法接入第三方身份源、无法跨系统单点登录、每个资源服务都被迫强依赖共享 Redis。服务边界刚刚稳定，是切换协议成本最低的时点。

## What Changes

- 在 `iboot-auth` 内引入 Spring Authorization Server（Spring Security 7.0 起已并入），提供标准的 OAuth2 授权码 + PKCE 与 OIDC 发现端点。
- **BREAKING** 令牌格式：由 HMAC 共享密钥（HS256）改为非对称 JWK（RS256），资源服务器改为验签 JWK 并读取令牌声明，不再把令牌当会话键。
- **BREAKING** 登录流程：前端不再直传账号密码换取令牌，改为浏览器跳转到认证服务完成登录，再以授权码换令牌。
- 采用**混合会话模型**：令牌自包含，共享 Redis 保留为撤销名单与在线名单，以保住独占会话、强制下线、在线用户列表与滑动续期四项既有能力。
- 登录页迁入认证服务并沿用现有视觉主题；滑块验证码随之迁移。
- 新增静默续期能力，维持「闲置 30 分钟掉线」的既有语义，不因令牌有效期变短而退化。
- 保留账号锁定、失败重试计数、登录日志、注册开关等全部既有业务规则，宿主由 MVC 控制器改为认证框架的认证提供者与成功/失败处理器。
- 双栈窗口：旧 HS256 令牌与新 JWK 令牌并存校验一个发布周期，避免发布瞬间全体在线用户被强制下线。
- 前端改动限定在登录页、用户状态、请求拦截、路由守卫与认证 API 五个文件；43 个业务视图不动。
- 回归装置适配：登录用例改为令牌端点换取，接口基线纳入标准端点。

## Capabilities

### New Capabilities

（无新增能力。本次变更改变的是既有认证能力的行为契约，不引入新的能力域。）

### Modified Capabilities

- `auth-service`: 认证协议由「用户名密码直传 + 共享 Redis 会话」改为 OAuth2 授权码 + OIDC；会话的事实来源由「仅共享 Redis」改为「自包含令牌 + Redis 撤销/在线名单」；新增登录体验维持要求，覆盖静默续期、在线用户可见性与登录页归属。

## Impact

**受影响模块**

| 模块 | 影响 |
|---|---|
| `iboot-kernel` | 鉴权模型重写：`JwtAuthenticationFilter` 由查 Redis 改为验 JWK + 读声明；鉴权模型的唯一收口，改一次全服务生效 |
| `iboot-auth` | 协议实现主体：授权服务器配置、客户端注册、JWK 密钥、登录页、令牌端点、撤销/在线名单维护 |
| `iboot-admin` | 在线用户列表与强制下线改为读在线名单；`/api/auth/scope` 契约不变 |
| `iboot-gateway` | 新增认证服务标准端点的路由规则，白名单前缀扩展 |
| `iboot-portal` | 登录页、用户状态、请求拦截、路由守卫、认证 API 五个文件；SSE 与文件下载的令牌传参需要适配短令牌 |

**不受影响**：43 个业务视图、24 个管理端控制器、`iboot-file` 与 `iboot-ai` 的业务逻辑；服务间以调用者身份代理下游请求的三处客户端（`AdminApiClient`、`PermissionScopeClient`、`AdminOrgSnapshotClient`）只做 Bearer 透传，无需改动。

**依赖与配置**：新增 `spring-boot-starter-security-oauth2-authorization-server`（Boot 4.0.3 BOM 已托管）；新增签名密钥对、客户端注册表、回调地址白名单；双栈窗口期需要同时分发旧共享密钥与新公钥。

**回归与运维**：接口基线重录（新增标准端点）、登录用例改写、迁移登记更新；发布需要一次全体服务协同重启，窗口期内的旧令牌子集需持续可验证。

**非目标**：第三方身份源联邦登录（企业微信/钉钉/GitHub）、SAML、多租户、`iboot-system` 拆分、43 个业务视图的任何改造。
