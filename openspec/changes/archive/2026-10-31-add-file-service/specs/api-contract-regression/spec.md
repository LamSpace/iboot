# Spec Delta

## ADDED Requirements

### Requirement: 服务迁移的路径守恒与响应等价

把一个接口从一个服务迁到另一个服务时，系统 SHALL 能自动证明这次迁移是「纯搬家」，而不是靠冒烟用例间接推断。

- 迁移前后，所有服务对外接口路径的**并集** MUST 完全相同；任何一个路径消失或凭空出现都 MUST 导致检查失败。
- 从服务 A 迁到服务 B 的路径 MUST 被显式登记，登记内容包含来源服务、目标服务与路径清单。
- 对一组固定请求，迁移前后 MUST 返回相同的状态码与归一化后的响应体；归一化规则与接口基线一致（去除易变字段、稳定排序）。
- 迁移时必须保留「改回路由即可回滚」的能力：回滚期间由旧实现写入的数据，在切回新实现后 MUST 仍然可见。

#### Scenario: 路径集合在迁移前后保持不变

- **WHEN** 执行服务迁移后运行路径守恒检查
- **THEN** 所有服务快照的路径并集与迁移前完全一致
- **WHEN** 某个路径既未出现在任何服务快照中，也未登记为删除
- **THEN** 检查失败并指出该路径

#### Scenario: 迁移路径必须登记

- **WHEN** 路径 P 从服务 A 的基线中消失并出现在服务 B 的基线中
- **THEN** 若该迁移已登记，检查通过
- **AND** 若未登记，检查失败并列出 P 的来源与目标

#### Scenario: 迁移前后响应等价

- **WHEN** 对固定请求集在迁移前直连原服务录下响应，迁移后经网关重放同一组请求
- **THEN** 每条请求的状态码与归一化响应体完全一致
- **AND** 任一差异导致检查失败并指出具体请求与字段

#### Scenario: 回滚后数据仍可见

- **WHEN** 迁移完成、流量切到新服务后，将路由回退到旧实现并写入一条数据
- **THEN** 再把路由切回新服务时，该数据仍能被查询到
