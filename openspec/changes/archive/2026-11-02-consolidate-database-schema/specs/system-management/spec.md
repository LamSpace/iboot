# Spec Delta

## REMOVED Requirements

### Requirement: 系统域数据的跨 schema 只读契约

**Reason**: 数据库合并为单一 schema 后，跨 schema 的物理边界不再存在；继续以「跨 schema」表述会误导实现。

**Migration**: 同一份消费契约改由下面的「系统域数据的只读消费契约」表达，登记的表与列清单不变，只把边界从 schema 改为表。

## ADDED Requirements

### Requirement: 系统域数据的只读消费契约

其余服务 SHALL 以同库只读的方式消费系统域数据，该方式 MUST 被作为长期模式接受，而不是待消除的临时债务；同时 MUST 把消费面收敛为显式、有测试锁定的契约。

- 每个消费方 MUST 只读取其契约中登记的表与列，MUST NOT 依赖未登记的表或列。
- 消费方 MUST 以只读方式访问，不得写入系统域拥有的任何表。
- 契约 MUST 在项目文档中逐服务登记表名、列名与用途，并在消费方以测试锁定列名与语义。
- 系统域 MUST 把被消费的表列视为对外接口：删除或重命名列 MUST 视为破坏性变更，需要与消费方同批发布。
- 消费方在系统域不可用时的行为 MUST 是明确错误，不得静默返回空集合、默认值或降级为不过滤。

#### Scenario: 契约外访问被发现

- **WHEN** 某消费方新增对未登记表或列的读取
- **THEN** 该消费方的契约测试失败并指出未登记的字段

#### Scenario: 消费方只读

- **WHEN** 检查任一消费方的数据库访问代码
- **THEN** 对系统域表的语句只有查询，没有写入或结构变更

#### Scenario: 系统域不可用时消费方给出明确错误

- **WHEN** 系统服务停止且某消费方需要读取用户信息
- **THEN** 该消费方返回可辨识的业务错误
- **AND** 不返回空列表并当作正常结果

## MODIFIED Requirements

### Requirement: 聚合视图对日志数据的只读消费

仪表盘与统计视图 SHALL 留在系统服务内，并只读监控服务拥有的登录日志与操作日志表；该方式 MUST 被作为长期模式接受。

- 该消费 MUST 只读取聚合所需的表与列，MUST NOT 写入审计表。
- 该消费 MUST NOT 改为对监控服务的同步远程调用，除非同时证明仪表盘在监控服务不可用时仍能返回可用结果。
- 审计表结构变更 MUST 视为破坏性变更，与消费方同批发布。

#### Scenario: 监控服务不可用时仪表盘仍可用

- **WHEN** 监控服务停止运行
- **THEN** 仪表盘与统计接口仍返回成功响应
- **AND** 日志统计数字取自最近一次可读的数据

#### Scenario: 聚合视图不影响审计写入

- **WHEN** 仪表盘与统计接口被频繁调用
- **THEN** 审计表的写入路径不受影响
- **AND** 审计记录不因读取而减少或改变
