# Spec Delta

## MODIFIED Requirements

### Requirement: 认证写入的过渡期边界

过渡期内认证服务 SHALL 直连共享数据库完成登录所需的数据读写：用户与角色数据来自系统域拥有的表，登录日志写入监控服务拥有的审计表；这些访问 MUST 被登记为临时状态，并附退出条件。

- 允许的读操作 MUST 仅限登录与注册所需的用户、角色、菜单与参数数据。
- 允许的写操作 MUST 仅限：更新 `sys_user` 的最后登录信息、注册时插入 `sys_user`、插入登录日志。
- 登录日志 MUST 写入监控服务拥有的审计表，MUST NOT 另建同名表。
- 认证服务 MUST NOT 修改其他服务的业务表。
- 登录日志写入失败 MUST NOT 导致登录失败。

#### Scenario: 登录成功更新最后登录信息

- **WHEN** 用户登录成功
- **THEN** 对应用户的最后登录 IP 与时间被更新
- **AND** 生成一条成功登录日志

#### Scenario: 登录日志落入审计表

- **WHEN** 一次登录成功或失败
- **THEN** 登录日志出现在监控服务拥有的审计表中
- **AND** 该记录可被日志查询与导出检索到

#### Scenario: 登录日志写入失败不影响登录

- **WHEN** 登录日志写入过程中发生异常
- **THEN** 登录仍然成功返回令牌

#### Scenario: 账号锁定语义不变

- **WHEN** 同一用户连续失败达到配置阈值
- **THEN** 返回与拆分前一致的锁定提示
- **AND** 锁定期间即使密码正确也拒绝登录
