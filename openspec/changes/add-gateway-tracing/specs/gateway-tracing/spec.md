# Spec Delta

## Purpose

让网关作为链路入口，为每个转发请求产生可查询的服务端 span，并把追踪上下文传给下游服务，使一次用户请求在追踪系统里是一条完整链路而不是若干条互不相干的片段。

## ADDED Requirements

### Requirement: 转发请求产生服务端 span

网关 MUST 为每一个经路由转发的请求创建一个服务端 span。

- span MUST 携带当前服务的标识、请求方法与路径，使链路上能看出这一段属于网关。
- span MUST 在请求结束后结束，且其耗时覆盖网关处理该请求的全过程。
- 观测 MUST NOT 改变请求或响应的内容、状态码与转发目标。

#### Scenario: 转发请求出现在链路中
- **WHEN** 客户端经网关请求任一后端接口
- **THEN** 追踪系统里该请求存在一个属于网关的服务端 span
- **AND** 该 span 的路径与实际请求路径一致

#### Scenario: 观测不改变响应
- **WHEN** 同一请求分别在观测开启与关闭时发出
- **THEN** 两次返回的状态码与响应体一致

### Requirement: 追踪上下文传递给下游

网关 MUST 把入口请求的追踪上下文传给下游服务，使下游产生同一 TraceID 下的子 span。

- 传递 MUST 使用业界通行的标准格式。
- 下游服务 MUST 沿用网关产生的 TraceID，不得另起一条链路。
- 网关自身产生的上游调用 span MUST 与入口 span 处于同一链路，父子关系正确。

#### Scenario: 三服务同链路
- **WHEN** 一次请求经网关调用后端服务，该服务再调用另一个服务
- **THEN** 追踪系统里三个服务的 span 具有同一个 TraceID
- **AND** 父子关系为 网关入口 → 网关上游调用 → 下游服务

#### Scenario: 下游不另起链路
- **WHEN** 请求到达下游服务时网关已注入追踪上下文
- **THEN** 下游服务的 span 挂在网关的 span 之下，而不是成为新的根

### Requirement: 不与 actuator 观测重复

网关 MUST 对已有独立观测的路径不重复创建同级 span。

- 健康检查、指标等运维端点的观测行为 MUST 保持与本变更之前一致。
- 重复创建导致同一请求出现两条同级 span 时，视为未满足本要求。

#### Scenario: 运维端点不重复
- **WHEN** 请求指向运维端点
- **THEN** 该请求不因本变更而多出一条同级 span

### Requirement: 观测可整体关闭且故障不阻断请求

追踪 MUST 可整体关闭；观测组件自身出错时 MUST NOT 使请求失败。

- 关闭后 MUST 不再产生网关 span，但转发行为不变。
- 观测过程中的异常 MUST 被隔离，不得影响请求处理。

#### Scenario: 关闭追踪后业务不受影响
- **WHEN** 追踪被关闭
- **THEN** 请求正常返回，且不再产生网关 span

#### Scenario: 观测异常不影响请求
- **WHEN** 观测组件内部发生异常
- **THEN** 请求仍然正常完成

### Requirement: 验证方式不依赖时间窗

对链路是否贯通的验证 MUST NOT 依赖按时间范围检索追踪后端。

- 验证 MUST 能从一个可复现的来源取得 TraceID（例如服务日志或响应头），再按该标识查询链路。
- 验证 MUST 能在单元层面断言"观测是否被创建"，从而把"组件未执行"与"数据未导出"区分开。

#### Scenario: 按标识验证三服务链路
- **WHEN** 执行链路验证
- **THEN** 结果明确给出三个服务是否出现在同一 TraceID 下
- **AND** 验证结果不随系统时钟变化而失真

#### Scenario: 单元层区分未执行与未导出
- **WHEN** 观测组件没有被执行，或执行了但没有导出
- **THEN** 单元测试能指出是哪一种情况
