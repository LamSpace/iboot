# Spec Delta

## Purpose

定义数据库的建库与版本管理由谁负责、服务怎样获得可用的 schema，以及结构变更以什么顺序发布，使多服务退出「各自迁移、启动顺序敏感」的状态。

## ADDED Requirements

### Requirement: 数据库版本管理集中在一个执行者

数据库的建库与结构变更 SHALL 由一个独立的、一次性的执行者完成，服务进程不再承担迁移职责。

- 该执行者 MUST 独占全部迁移脚本，服务模块 MUST NOT 再打包或执行迁移。
- 一次运行 MUST 完成建库（不存在时创建）与全部未应用的迁移。
- 全部迁移成功时 MUST 以 0 退出；任一迁移失败时 MUST 以非零退出，且 MUST NOT 继续执行后续迁移。
- 重复运行 MUST 是幂等的：已应用的迁移不再重复执行。
- 执行者的输出 MUST 能说明每个 schema 的当前版本与本次应用了哪些迁移。

#### Scenario: 空库一次建好
- **WHEN** 在空数据库上执行一次初始化
- **THEN** 目标数据库与全部表被创建
- **AND** 进程以 0 退出

#### Scenario: 重复执行不重复应用
- **WHEN** 在已完成迁移的数据库上再次执行
- **THEN** 没有任何迁移被重复执行
- **AND** 进程以 0 退出

#### Scenario: 迁移失败阻断后续
- **WHEN** 某个迁移脚本执行失败
- **THEN** 进程以非零退出
- **AND** 其后的迁移不被执行

### Requirement: 服务只连接数据库，不改变结构

服务进程 SHALL 只使用已经建好的结构，MUST NOT 在启动时执行建表或改表。

- 服务的启动 MUST NOT 依赖迁移执行者已经运行，但 MUST 在其未运行时以明确错误暴露「表不存在」。
- 服务 MUST NOT 打包迁移脚本，MUST NOT 以任何方式创建或修改表结构。
- 服务与迁移执行者 MUST 使用同一个数据库连接信息，避免出现「迁移到 A 库、服务连 B 库」。

#### Scenario: 服务不触发迁移
- **WHEN** 服务在已初始化的数据库上启动
- **THEN** 启动过程中不产生任何 DDL 语句

#### Scenario: 未初始化时错误明确
- **WHEN** 服务在空数据库上启动并收到请求
- **THEN** 返回明确错误，日志指出缺少表
- **AND** 服务不会自行建表

### Requirement: 单一数据库身份与表级所有权

所有服务 SHALL 共享同一个数据库身份（同一个 schema 名），表的写入所有权改由表级约定表达。

- 数据库名 MUST 由配置单一指定，服务与迁移执行者 MUST 一致。
- 每张表 MUST 有唯一的所有者服务；所有者是唯一允许改变其结构与提供写入路径的一方。
- 非所有者 MAY 只读被登记的表与列，MUST NOT 写入他人的表。
- 跨服务的只读消费 MUST 以表名为限，不得依赖未登记的表或列。

#### Scenario: 服务读取他人拥有的表
- **WHEN** 监控服务之外的某个服务读取审计表
- **THEN** 该读取使用表名即可完成，不需要库名前缀
- **AND** 该表与列已登记在消费契约中

#### Scenario: 非所有者写入被拒
- **WHEN** 某服务尝试写入不属于它的表
- **THEN** 该写入属于既有登记例外之外的越权行为，评审拒绝合入

### Requirement: 迁移变更遵循先扩展后收缩

结构变更 SHALL 保证滚动发布期间旧实例仍可运行，避免发布与迁移互相阻塞。

- 一次发布 MUST 只做扩展性变更（加表、加列、加索引、放宽约束）。
- 删除列、改类型、收紧约束等收缩性变更 MUST 放到后续发布，且 MUST 在确认旧实例已全部下线后执行。
- 迁移版本号 MUST 全局唯一且单调，跨服务并行开发时 MUST NOT 产生相同版本号。
- 每个迁移 MUST 在版本号或文件名中体现所属服务，便于定位来源。

#### Scenario: 滚动发布期间旧实例仍可用
- **WHEN** 先执行迁移、再逐步替换服务实例
- **THEN** 尚未替换的旧实例处理请求时不因新结构而失败

#### Scenario: 并行开发不撞版本号
- **WHEN** 两个服务在同一时间段各自新增一条迁移
- **THEN** 两条迁移的版本号不同
- **AND** 执行顺序确定且可重复

### Requirement: 测试使用同一份迁移

集成测试 SHALL 用与生产相同的一份迁移建立 schema，不得维护第二套建表脚本。

- 测试 MUST 通过迁移执行者提供的入口建立 schema。
- 测试 MUST NOT 在测试资源中保留一份独立的建表 SQL。
- 迁移变更导致测试失败时 MUST 视为结构契约变化，而不是测试环境问题。

#### Scenario: 测试从生产迁移建立 schema
- **WHEN** 运行一个需要数据库的集成测试
- **THEN** 测试用与生产相同的迁移建立临时 schema
- **AND** 测试断言的表与列与生产一致
