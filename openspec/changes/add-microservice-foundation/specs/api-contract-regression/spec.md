# Spec Delta

## Purpose

用可重复执行的自动化检查证明服务拆分没有改变外部可见的接口契约与权限边界，并在发生漂移时于构建阶段就失败，而不是等到用户发现。

## ADDED Requirements

### Requirement: 接口契约基线的捕获与维护

系统 SHALL 能从每个后端服务导出其全部对外接口的结构描述（路径、方法、请求参数、响应结构），并保存为纳入版本管理的基线。

- 基线 MUST 在「已知正确」的状态下捕获，即改造开始之前。
- 基线 MUST 经过归一化：去除环境相关的地址、排序稳定、剔除易变示例值，使无关差异不产生噪声。
- 每个服务 MUST 有独立的基线文件，使单个服务的接口变化可以被单独审阅。

#### Scenario: 从服务导出接口清单
- **WHEN** 对某个正在运行的服务执行导出
- **THEN** 得到该服务全部对外接口的路径、方法与参数结构

#### Scenario: 基线可重复生成
- **WHEN** 在未改动代码的情况下连续导出两次
- **THEN** 两次结果归一化后完全相同

#### Scenario: 基线按服务分隔
- **WHEN** 同时存在多个服务
- **THEN** 每个服务各有一份基线文件，互不覆盖

### Requirement: 契约零漂移判定

服务拆分与改造 MUST NOT 改变任何既有对外接口的路径、方法、必填参数与响应结构。

- 改造后的导出结果与基线比较 MUST 完全一致；不一致时检查 MUST 失败并指出具体差异。
- 允许的差异 MUST 显式登记（例如新增接口），且每条登记 MUST 说明理由。
- 检查 MUST 在构建或持续集成中自动执行，不得依赖人工发起。

#### Scenario: 无变化时检查通过
- **WHEN** 改造未改变任何接口，执行契约检查
- **THEN** 检查通过

#### Scenario: 路径变化导致失败
- **WHEN** 某接口的路径或方法与基线不一致
- **THEN** 检查失败并指出该接口的差异

#### Scenario: 未登记的差异导致失败
- **WHEN** 出现与基线不同的差异，且未登记为允许项
- **THEN** 检查失败

#### Scenario: 已登记的新增接口不导致失败
- **WHEN** 新增了一个接口并已显式登记
- **THEN** 检查通过，且新增接口出现在新的基线中

### Requirement: 关键链路端到端冒烟

系统 SHALL 提供一组固定的端到端用例，覆盖用户最常走且最容易因拆分受损的链路。

- 用例集 MUST 至少覆盖：登录、用户信息变更、文件上传与下载、实时推送消息接收、数据备份触发、审批流转。
- 每条用例 MUST 断言状态码与关键响应字段，而不只是「请求不报错」。
- 用例 MUST 能在一条命令下重复执行，且不依赖人工准备数据。

#### Scenario: 拆分后关键链路仍可用
- **WHEN** 任一服务完成迁移后执行冒烟用例集
- **THEN** 全部用例通过

#### Scenario: 链路中断被定位
- **WHEN** 某条链路因拆分受损
- **THEN** 对应用例失败并指出是哪一条链路

### Requirement: 权限边界矩阵回归

系统 SHALL 以「角色 × 接口 × 期望结果」的固定矩阵验证权限行为，覆盖接口级权限与数据范围权限。

- 矩阵 MUST 同时包含应当被允许与应当被拒绝的用例，只测允许路径不足以发现越权。
- 拆分前后同一矩阵的判定结果 MUST 完全一致。
- 矩阵中每条用例 MUST 说明其验证的权限维度（功能权限或数据可见范围）。

#### Scenario: 拆分后权限行为一致
- **WHEN** 对同一角色的同一接口执行权限矩阵
- **THEN** 允许/拒绝的判定与拆分前一致

#### Scenario: 越权被检出
- **WHEN** 某接口在拆分后错误地允许了低权限角色
- **THEN** 对应用例失败并指出该角色与该接口

#### Scenario: 数据范围收紧被检出
- **WHEN** 某角色因拆分后数据范围失效而看到了更多数据
- **THEN** 对应用例失败

### Requirement: 检查结果作为构建门禁

上述检查的任何失败 MUST 使构建或发布流程失败，不得以告警或忽略的方式放行。

- 失败输出 MUST 足以定位问题：指出哪个服务、哪条接口或哪条用例。
- 检查结果 MUST 可被本地开发者以同一条命令复现，避免「只在持续集成上失败」。

#### Scenario: 失败阻断合并
- **WHEN** 契约、路由覆盖、冒烟或权限矩阵任一检查失败
- **THEN** 构建流程失败，变更不能被合并

#### Scenario: 本地可复现
- **WHEN** 开发者在本地执行与持续集成相同的命令
- **THEN** 得到与持续集成一致的检查结果
