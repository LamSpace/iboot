# operation-logging Specification

## Purpose

让拆分后的各个服务仍能把带 `@Log` 的操作审计写入同一张可查询的审计表，并让写入失败以错误日志和指标可见，而不是静默丢失。

## Requirements

### Requirement: 跨服务审计记录的可见性

监控服务 SHALL 能看到所有服务写入的审计记录，不得因服务拆分而只显示部分数据。

- 查询结果 MUST 包含全部拆分服务产生的记录，字段语义与拆分前一致。
- 清理与导出 MUST 作用于同一份审计数据，不得漏掉任何服务写入的记录。
- 查询与导出 MUST 沿用拆分前的权限码与数据范围语义。

#### Scenario: 拆分服务的操作出现在日志页

- **WHEN** 用户在文件服务完成一次上传或删除
- **THEN** 操作日志查询返回该次操作
- **AND** 操作人、操作类型与结果字段与拆分前一致

#### Scenario: 清理覆盖全部服务

- **WHEN** 管理员执行操作日志清理
- **THEN** 拆分服务写入的记录按相同保留策略被清理
- **AND** 不会只清理单个服务的记录

### Requirement: 审计日志的写入目标与一致性

系统 SHALL 把带有 `@Log` 注解的操作记录写入一个可配置的审计表；该表由监控服务拥有并通过集中迁移管理，其他服务 MUST 在同一个数据库内写入。

- 写入目标 MUST 在服务启动时校验；非法目标 MUST 使启动失败，而不是在运行期写入未知表。
- 写入 MUST 是旁路行为：审计存储不可用时，业务请求 MUST 仍然成功。
- 写入失败 MUST 可观测：至少产生错误级日志，并使运维能从指标或日志判断该服务的审计记录正在丢失。
- 审计表的结构 MUST 只由拥有者定义；写入方 MUST NOT 创建或修改其结构。
- 写入方 MUST NOT 为审计表另建一张同名表，也 MUST NOT 在其它数据库中登记同名目标。

#### Scenario: 拆分服务写入共享审计表

- **WHEN** 拆分服务处理一个带 `@Log` 的请求
- **THEN** 审计表出现一条包含操作人、操作内容与结果的记录
- **AND** 记录与该服务的应用名可区分

#### Scenario: 非法写入目标导致启动失败

- **WHEN** 配置的审计表名不是合法的标识符
- **THEN** 服务启动失败并给出明确原因
- **AND** 不会以默认表名继续启动

#### Scenario: 审计存储不可用

- **WHEN** 审计表不可写
- **THEN** 业务请求仍然成功
- **AND** 日志中出现可定位的错误，且同一服务不会无限重复告警

#### Scenario: 所有写入方目标一致

- **WHEN** 检查全部服务的审计写入配置
- **THEN** 它们指向同一张由监控服务拥有的表
- **AND** 不存在按库名前缀区分的第二份审计目标
