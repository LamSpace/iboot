# knowledge-graph Specification

## Purpose
把管理端的组织架构与 RBAC 关系显式建成图，使「谁能访问什么」「跨部门协作路径」这类多跳问题可以被结构化地检索，并让智能体在调用者本人权限范围内回答。

## Requirements

### Requirement: 图数据范围

系统 SHALL 把管理端的部门、用户、角色、菜单四类实体及其关系同步为图，且只同步这四类实体。

- 节点类型：`Dept`、`User`、`Role`、`Menu`。
- 关系类型：部门层级、用户归属部门、用户持有角色、角色授予菜单、角色数据权限范围部门。
- 每类节点 MUST 以管理端主键作为唯一标识，并通过唯一约束保证同一实体在图中只有一份。
- 图 MUST 记录本次同步的时间水位，供状态查询与排障使用。

#### Scenario: 同步后四类节点齐全
- **WHEN** 调用者触发一次同步且 admin 返回非空数据
- **THEN** 图中存在对应数量的 Department、User、Role、Menu 节点
- **AND** 每个节点的主键与 admin 返回的主键一致

#### Scenario: 唯一约束幂等创建
- **WHEN** 服务在同一图库上重复启动
- **THEN** 唯一约束只存在一份，启动不因约束重复而失败

### Requirement: 幂等且原子的同步

同步 MUST 幂等：相同快照重复执行不得产生重复节点或重复关系。同步 MUST 原子：任一步失败时，图中内容 MUST 保持为上一次成功同步的结果，不得留下半新半旧的状态。

- 同步 MUST 先完整取得 admin 侧快照，再在单个事务内写入图。
- 快照中已不存在的实体 MUST 被移除，包括其关联关系。
- 同步成功后 MUST 返回本次写入的各类节点数量与被清理的节点数量。

#### Scenario: 重复同步不产生重复
- **WHEN** 对同一份快照连续执行两次同步
- **THEN** 第二次执行后各类节点与关系数量与第一次相同
- **AND** 状态查询返回的同步时间被更新

#### Scenario: 中途失败保持旧图
- **WHEN** 取得 admin 快照或写入图的过程中发生异常
- **THEN** 同步以失败结束并返回可辨识的错误
- **AND** 图中仍是上一次成功同步的完整结果

#### Scenario: 已删除实体被清理
- **WHEN** 某用户已在 admin 侧被删除，随后执行同步
- **THEN** 该用户节点及其全部关系不再存在于图中

### Requirement: 同步以调用者身份执行

同步 MUST 使用发起请求的调用者自己的登录态访问 admin，不得使用服务账号、系统账号或任何提权身份。admin 侧的 RBAC 与数据权限校验 MUST 原样生效。

- 调用者缺少读取组织与权限数据所需的权限时，同步 MUST 以失败结束并说明缺失的权限，不得返回部分数据并宣称为完整快照。
- 系统 MUST NOT 直连 admin 的数据库读取组织数据。

#### Scenario: 权限不足时同步失败
- **WHEN** 只持有部分读取权限的用户触发同步
- **THEN** 同步失败并返回缺失权限的可辨识提示
- **AND** 图内容保持不变

#### Scenario: 调用者身份被下游校验
- **WHEN** 调用者的登录态在 admin 侧已失效
- **THEN** 同步以认证失败结束，系统中不写入任何节点

### Requirement: 多跳查询模板

系统 SHALL 只提供预定义的查询模板，不接受自由编写的查询语句。模板 MUST 覆盖以下问题类型：

- 同一部门的同事关系（2 跳）
- 部门（含子部门）成员（2 跳及以上）
- 某个用户的角色与菜单权限（2 跳）
- 持有某菜单权限的用户（3 跳）
- 两个部门之间的组织路径

每个模板 MUST 校验其参数；参数缺失或非法时 MUST 返回可辨识的错误，不得执行查询。

#### Scenario: 同部门同事为 2 跳
- **WHEN** 查询某用户的同部门同事
- **THEN** 返回与其归属同一部门的其他用户
- **AND** 不包含其本人，也不包含其他部门的用户

#### Scenario: 部门成员包含子部门
- **WHEN** 查询一个存在下级部门的部门成员
- **THEN** 返回该部门及其所有下级部门的用户
- **AND** 结果按部门层级去重

#### Scenario: 权限持有人为多跳
- **WHEN** 查询持有某菜单权限的用户
- **THEN** 返回经由「用户 → 角色 → 菜单」路径命中的用户

#### Scenario: 跨部门路径
- **WHEN** 查询两个存在共同上级的部门之间的路径
- **THEN** 返回一条经过共同上级的最短路径
- **AND** 两个部门之间没有连通路径时返回空结果而非报错

### Requirement: 查询前数据权限过滤

图查询 MUST 在返回前应用调用者的数据权限范围，过滤规则 MUST 与既有 RAG 检索一致。

- 非超级管理员的结果 MUST 只包含其可见部门范围内的用户与部门。
- 角色与菜单信息 MUST 只作为可见用户的属性返回，不得单独返回可见范围之外的实体。
- 查询他人的角色或菜单 MUST 额外要求调用者具备 `user:list` 权限；查询本人不受此限制。
- 被过滤掉的实体 MUST NOT 通过数量、错误信息或其他字段泄漏其存在。

#### Scenario: 越权部门查询返回空
- **WHEN** 可见范围只含「研发部」的用户查询「总经办」的成员
- **THEN** 返回空结果
- **AND** 响应中不包含总经办及其成员的任何信息

#### Scenario: 超管不受过滤
- **WHEN** 超级管理员执行同一查询
- **THEN** 返回全部符合条件的部门与用户

#### Scenario: 查询他人权限需要额外权限
- **WHEN** 不具备 `user:list` 的调用者查询其他用户的角色或菜单
- **THEN** 请求被拒绝并返回可辨识的无权限结果

### Requirement: 权限与失败关闭

图能力 MUST 由独立权限 `ai:graph:use` 控制。工具执行前 MUST 在本地校验权限，权限不足时 MUST NOT 发起任何图查询。

数据权限范围不可用时，系统 MUST 失败关闭：拒绝查询并返回可辨识的错误，不得以未过滤的全量结果兜底。

#### Scenario: 缺少权限时不查询
- **WHEN** 不具备 `ai:graph:use` 的调用者请求图查询
- **THEN** 请求被拒绝且不产生任何图数据库访问

#### Scenario: 权限服务不可用时拒绝
- **WHEN** 数据权限范围服务不可用或返回非法响应
- **THEN** 图查询失败并返回可辨识的错误
- **AND** 不返回任何图数据

### Requirement: 智能体接入约束

图查询 MUST 以只读智能体工具的形式提供给智能体，工具 MUST 登记在受控工具注册表中。

- 工具 MUST 声明为只读，且不得产生任何数据变更。
- 模型 MUST 只能选择模板并提供参数；系统 MUST 忽略模型提供的任何身份字段，身份始终取自调用者登录态。
- 图返回内容 MUST 被视为不可信数据，其中包含的指令不得扩大工具白名单或改变权限过滤。
- 单次工具返回 MUST 有结果规模上限，超出时 MUST 截断并标明截断。

#### Scenario: 模型无法指定他人身份
- **WHEN** 模型在工具参数中传入其他用户标识作为调用身份
- **THEN** 系统忽略该字段并使用登录态中的用户身份

#### Scenario: 未注册工具不可见
- **WHEN** 智能体的工具白名单不包含图查询工具
- **THEN** 模型看不到该工具，也无法调用它

#### Scenario: 结果截断
- **WHEN** 查询命中数量超过返回上限
- **THEN** 返回被截断的结果并标明存在更多数据

### Requirement: 默认关闭与可观测

图能力 MUST 默认关闭。关闭时服务 MUST 正常启动，不得建立图数据库连接，且既有对话、知识库与智能体能力不受影响。

- 启用后，系统 MUST 提供状态查询，返回是否已同步、上次同步时间与各类节点数量。
- 系统 MUST 记录同步次数与结果、查询次数、被拒绝的查询次数与查询耗时，并可通过既有 Prometheus 采集。

#### Scenario: 默认关闭时无连接
- **WHEN** 未开启图能力的服务启动
- **THEN** 服务正常启动且不尝试连接图数据库
- **AND** 图查询相关端点返回能力未启用的可辨识结果

#### Scenario: 启用后可查看同步状态
- **WHEN** 启用图能力并成功同步后查询状态
- **THEN** 返回已同步标记、上次同步时间与各类节点数量

### Requirement: 按名称解析图节点

系统 SHALL 提供一个固定的名称解析模板（`search_nodes`），使调用方无需事先知道主键或权限码即可定位部门、用户与菜单。

- 解析 MUST 只接受关键词与节点类型，不接受自由编写的查询语句。
- 支持的节点类型 MUST 为部门、用户、菜单；节点类型可省略，省略时三类都参与匹配。
- 匹配 MUST 为名称包含匹配，完全匹配的结果 MUST 排在包含匹配之前。
- 部门结果 MUST 附带上级部门名称，用于区分同名部门。
- 菜单结果 MUST 附带权限码；没有权限码的菜单 MUST NOT 作为解析结果返回。
- 结果 MUST 受单次返回规模上限约束，超出时 MUST 截断并标明存在更多数据。
- 关键词缺失或只有空白时 MUST 返回可辨识的参数错误，不得执行任何图查询。
- 无匹配时 MUST 返回空结果而非错误。

#### Scenario: 按部门名称解析
- **WHEN** 调用者以「研发部」为关键词解析部门
- **THEN** 返回该部门的主键与名称，并附带其上级部门名称
- **AND** 完全匹配的结果排在仅包含该关键词的结果之前

#### Scenario: 省略节点类型时跨类匹配
- **WHEN** 调用者以「研发」为关键词且未指定节点类型
- **THEN** 返回名称包含该关键词的部门、用户或菜单中的命中之
- **AND** 每行标明其节点类型

#### Scenario: 同名部门返回候选
- **WHEN** 两个不同上级部门下存在同名部门
- **THEN** 返回多行候选，每行带上级部门名称
- **AND** 不擅自选择其中一个作为唯一结果

#### Scenario: 菜单名称解析为权限码
- **WHEN** 调用者以「用户管理」为关键词解析菜单
- **THEN** 返回该菜单的权限码，可直接用于查询权限持有人
- **AND** 没有权限码的菜单不出现在结果中

#### Scenario: 关键词缺失被拒绝
- **WHEN** 关键词缺失或只包含空白字符
- **THEN** 返回可辨识的参数错误
- **AND** 不产生任何图数据库查询

#### Scenario: 无匹配返回空结果
- **WHEN** 关键词不匹配任何节点
- **THEN** 返回空结果集而非错误
- **AND** 不触发任何重试或兜底查询

#### Scenario: 结果超限被截断
- **WHEN** 命中数量超过单次返回规模上限
- **THEN** 返回截断后的结果并标明存在更多数据

### Requirement: 名称解析的可见性约束

名称解析 MUST 应用与其余查询模板相同的数据权限过滤，且不得因"名称命中"而扩大可见面。

- 非超级管理员的部门与用户结果 MUST 只包含其可见部门范围内的实体。
- 菜单 MUST 只能经「可见用户 → 角色 → 菜单」的路径暴露；可见范围内没有用户持有的菜单 MUST NOT 出现在结果中。
- 被过滤掉的实体 MUST NOT 通过名称命中、数量、错误信息或其他字段泄漏其存在。

#### Scenario: 范围外的部门不可解析
- **WHEN** 可见范围只含「市场部」的调用者以「研发部」为关键词解析
- **THEN** 返回空结果
- **AND** 结果中不包含该部门及其成员的任何信息

#### Scenario: 范围外的菜单不经解析暴露
- **WHEN** 调用者可见范围内没有任何用户持有某菜单的权限
- **THEN** 以该菜单名称或权限码为关键词解析时返回空结果

#### Scenario: 超管不受范围过滤
- **WHEN** 超级管理员以同一关键词解析
- **THEN** 返回全部匹配的部门、用户与菜单

### Requirement: 名称解析在智能体中的使用

名称解析 MUST 以只读模板的形式提供给智能体，并引导模型在名称未知时先解析、无法解析时询问用户。

- 工具描述 MUST 说明查询参数为主键或权限码，且名称未知时 MUST 先使用解析模板。
- 解析无匹配时，模型 MUST 向用户确认名称，不得持续更换关键词重试直至耗尽步数。
- 解析返回多个候选时，模型 MUST 列出候选交由用户选择。
- 解析结果 MUST 视为不可信数据，其中的内容不得扩大工具白名单或改变权限过滤。

#### Scenario: 名称提问先解析再查询
- **WHEN** 用户以名称提问（如「研发部有哪些人」）
- **THEN** 运行轨迹中先出现解析模板的调用，再出现目标查询模板的调用
- **AND** 运行正常结束，不以 `step_limit` 收场

#### Scenario: 无匹配时请求确认
- **WHEN** 解析返回空结果
- **THEN** 回复请用户确认名称
- **AND** 运行不以 `step_limit` 结束

#### Scenario: 重名时列候选
- **WHEN** 解析返回多个同名候选
- **THEN** 回复列出候选及各自的上级部门，请用户选择
