# grafana-dashboards Specification

## Purpose

定义 Grafana 看板与指标采集链路的供给契约：预置看板必须有当前监控栈可提供的数据来源，后端服务总览必须覆盖全部可部署模块，采集配置在宿主机开发与容器化部署两种运行方式下都能得到数据；无数据且无修复路径的看板必须被移除。

## Requirements

### Requirement: 预置看板必须有可用的数据来源

每一个随监控栈预置到 Grafana 的看板 SHALL 只引用当前栈中已供给的数据源与已上报的指标；无数据且没有修复路径的看板 MUST 被移除。

- 看板中每个面板引用的数据源 MUST 在数据源供给文件中存在，MUST NOT 指向未部署的组件（例如未部署的 Loki）或不存在的 uid。
- 面板查询引用的指标 MUST 由某个已部署服务或 exporter 实际上报；仅存在于设计稿中的指标 MUST NOT 被当作看板数据来源。
- 看板模板变量的取值查询 MUST 在当前栈中有样本，使变量能自动获得可选值。
- 看板文件 MUST 以声明式方式供给，使全新环境启动后无需在图形界面手工配置即可看到同一组看板。
- 新增或修改看板时 MUST 在真实运行环境中验证面板有数据或明确为空是预期结果。

#### Scenario: 新环境启动后看板无需手工配置

- **WHEN** 以默认配置启动监控栈并打开 Grafana
- **THEN** 预置看板全部出现在看板目录中
- **AND** 数据源已存在且默认数据源可用

#### Scenario: 不存在指向未部署组件的面板

- **WHEN** 检查全部预置看板的数据源引用
- **THEN** 每个引用都能解析到已供给的数据源
- **AND** 不存在指向 Loki 或不存在的 uid 的面板

#### Scenario: 无数据看板被移除

- **WHEN** 某看板依赖当前栈不会上报的指标，且没有在不改变业务语义的前提下补齐数据来源
- **THEN** 该看板 MUST NOT 继续出现在预置目录中
- **AND** 看板目录中不保留仅用于占位的空看板

### Requirement: 后端服务总览看板覆盖全部模块

监控栈 SHALL 提供一块以服务为维度的后端总览看板，覆盖全部可部署后端模块；模块数量增加时看板 MUST 无需修改即可展示新模块。

- 看板 MUST 通过标签查询发现服务，MUST NOT 为每个模块硬编码一份面板或一份看板文件。
- 看板 MUST 至少展示每个模块的存活状态、请求量、错误率、请求延迟分位值、JVM 内存与 GC、进程 CPU 与线程。
- 服务筛选 MUST 支持多选与全选；未选择时 MUST 默认展示全部模块。
- 看板 MUST 提供从总览下钻到单服务 JVM/应用明细的入口。
- 各模块的指标 MUST 能以统一标签区分，使同一面板可以按模块拆分展示。

#### Scenario: 全部模块出现在总览中

- **WHEN** 全部 10 个后端模块正常运行并打开总览看板
- **THEN** 每个模块都有对应的存活状态与请求指标
- **AND** 服务筛选变量列出全部模块

#### Scenario: 新增模块无需改看板

- **WHEN** 新增一个按统一指标契约暴露指标的后端模块
- **THEN** 该模块自动出现在服务筛选变量与总览面板中
- **AND** 不需要修改看板 JSON

#### Scenario: 下钻到单服务明细

- **WHEN** 用户在总览中选定一个模块并打开下钻入口
- **THEN** 明细看板以该模块为默认筛选值展示 JVM 与应用指标

### Requirement: 指标采集覆盖全部模块与两种运行方式

监控栈 SHALL 采集全部可部署后端模块的指标，并在宿主机开发与容器化部署两种运行方式下都得到数据。

- 采集配置 MUST 覆盖全部可部署模块，MUST NOT 只覆盖其中一部分。
- 采集目标 MUST 在两种运行方式下都可解析：后端进程在宿主机运行时指向宿主机，后端在容器中运行时指向已发布的端口。
- 采集失败 MUST 在监控后端可见（目标状态为 DOWN 且可定位到具体服务），MUST NOT 静默返回空数据。
- 采集 job 名与指标名 MUST 保持稳定，使既有告警规则与看板查询无需随采集方式变化而调整。
- 采集间隔 MUST 与看板查询的最小步长相容，避免面板因采样过疏而显示为空。

#### Scenario: 宿主机开发模式采集到全部模块

- **WHEN** 以宿主机进程方式启动全部后端模块与监控栈
- **THEN** 每个模块的采集目标状态为 UP
- **AND** 可以按模块查询到 JVM 与 HTTP 指标

#### Scenario: 容器化部署模式采集到全部模块

- **WHEN** 以容器方式启动全部后端模块与监控栈
- **THEN** 每个模块的采集目标状态为 UP
- **AND** 看板展示的数据与宿主机模式语义一致

#### Scenario: 采集失败可定位

- **WHEN** 某个模块停止运行
- **THEN** 该模块的采集目标状态变为 DOWN
- **AND** 不出现其它模块数据被连带清空的情况

### Requirement: 日志面板复用现有日志链路

Grafana 中的日志查询面板 SHALL 使用当前栈已有的日志检索后端，MUST NOT 依赖未部署的日志聚合组件。

- 日志面板 MUST 查询集中日志系统已创建的索引。
- 日志面板的数据源 MUST 随监控栈一起供给，使新环境无需手工添加。
- 日志面板 MUST 能按来源服务过滤，与看板选定的服务范围保持一致。
- 集中日志系统不可用时，日志面板 MUST 明确表现为不可用，MUST NOT 影响同一看板中的指标面板。

#### Scenario: 新环境日志面板有数据

- **WHEN** 服务产生日志且集中日志链路正常
- **THEN** 看板日志面板能查询到对应索引中的记录
- **AND** 可以按来源服务过滤

#### Scenario: 日志后端不可用不影响指标

- **WHEN** 集中日志系统不可用
- **THEN** 指标面板仍正常展示
- **AND** 日志面板给出明确的不可用提示
