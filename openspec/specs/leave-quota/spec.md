# leave-quota Specification

## Purpose

为审批场景提供按人按年的请假次数额度：默认值可配置、首次扣减时懒创建，额度由系统服务独占管理，并通过内部接口支持跨服务原子扣减。

## Requirements

### Requirement: 年度次数额度与默认值

系统 SHALL 按 `user_id + year` 维护请假次数额度，记录总额度、已用次数与冻结次数。默认额度 MUST 来自系统配置 `leave.quota.default-count`；配置缺失或非法时按 10 处理。额度行 MUST 在首次扣减时懒创建，MUST NOT 预置全量用户。

#### Scenario: 首次扣减时创建额度

- **WHEN** 用户在某年首次扣减额度，且该用户该年没有额度行
- **THEN** 系统以默认额度创建一行，已用与冻结均为 0
- **AND** 本次扣减正常生效

#### Scenario: 跨年额度

- **WHEN** 用户在新的一年扣减额度
- **THEN** 系统为该年创建独立额度，不与上一年共享

#### Scenario: 默认值非法

- **WHEN** `leave.quota.default-count` 未配置、不是整数或不大于 0
- **THEN** 系统按 10 处理
- **AND** 记录一次可观测的告警日志

### Requirement: 本人额度查询

系统 SHALL 允许已登录用户查询自己指定年度的额度，返回总额度、已用次数与剩余次数。查询 MUST NOT 暴露其他用户的额度，MUST NOT 因查询而创建额度行。

#### Scenario: 查询本人额度

- **WHEN** 已登录用户请求当年的额度
- **THEN** 返回该用户的总额度、已用次数与剩余次数
- **AND** 不返回其他用户的数据

#### Scenario: 尚无额度行

- **WHEN** 用户当年尚无额度行
- **THEN** 按默认额度返回完整额度视图
- **AND** 不产生任何持久化副作用

#### Scenario: 未登录

- **WHEN** 未登录用户请求额度
- **THEN** 系统返回 401

### Requirement: 内部扣减接口

系统 SHALL 提供仅限服务间调用的扣减接口，按申请 ID 幂等扣减一次额度。接口 MUST 使用共享密钥鉴权，密钥缺失或不匹配时失败关闭。扣减 MUST 在单条更新语句中同时校验剩余额度，额度不足时返回明确错误且不产生任何变更。

#### Scenario: 扣减成功

- **WHEN** 调用方携带有效内部密钥，申请 ID 未扣减过，且剩余额度不少于 1
- **THEN** 已用次数增加 1，并写入一条扣减日志
- **AND** 返回成功

#### Scenario: 重复扣减

- **WHEN** 同一申请 ID 再次调用扣减
- **THEN** 不重复扣减
- **AND** 返回与首次一致的成功结果

#### Scenario: 额度不足

- **WHEN** 剩余额度为 0
- **THEN** 返回额度不足错误
- **AND** 已用次数与扣减日志均不变化

#### Scenario: 内部密钥无效

- **WHEN** 请求缺少内部密钥或密钥不匹配
- **THEN** 返回 401
- **AND** 不读取也不修改额度

#### Scenario: 并发扣减

- **WHEN** 剩余额度为 1 时两个不同申请并发扣减
- **THEN** 只有一个成功，另一个返回额度不足
- **AND** 已用次数最终为 1

### Requirement: 额度年份归属

额度扣减 MUST 落在请假开始时间所在年度；跨年请假只扣减开始时间所在年度的额度。

#### Scenario: 跨年请假

- **WHEN** 请假开始时间在上一年、结束时间在下一年
- **THEN** 只扣减上一年度的额度
- **AND** 下一年度额度不变

### Requirement: 额度冻结

系统 SHALL 在额度行上维护冻结次数，用于 TCC 预占。冻结 MUST 在剩余额度（总额度减已用减冻结）足够时原子增加；不足时 MUST 失败且不改变任何额度。冻结次数 MUST NOT 为负。

#### Scenario: 冻结成功

- **WHEN** 用户剩余额度不少于申请冻结的次数
- **THEN** 冻结次数原子增加对应次数
- **AND** 已用次数与总额度不变

#### Scenario: 冻结不足

- **WHEN** 用户剩余额度少于申请冻结的次数
- **THEN** 冻结失败并返回明确错误
- **AND** 冻结与已用次数均不变化

#### Scenario: 冻结不出现负数

- **WHEN** 对同一用户重复执行释放
- **THEN** 冻结次数不会低于 0

### Requirement: 冻结释放与划转确认

系统 SHALL 在取消时释放冻结，在确认时释放冻结并调整相关用户的总额度。确认与释放 MUST 幂等，重复执行不得重复加减。

#### Scenario: 取消释放

- **WHEN** 划转被取消
- **THEN** 划出方的冻结次数减少对应次数
- **AND** 双方的总额度不变

#### Scenario: 确认划转

- **WHEN** 划转被确认
- **THEN** 划出方冻结减少、总额度减少对应次数
- **AND** 划入方总额度增加对应次数

#### Scenario: 重复确认

- **WHEN** 同一划转被重复确认
- **THEN** 额度只调整一次
- **AND** 返回成功
