## 1. 项目简介

iBoot 是一个以后台管理系统为载体、以「五条 Native」为工程目标的技术实践项目：
在可运行的通用管理平台上，把微服务边界、零信任、AI 执行单元、可观测与云原生发布
逐条做成带验收判据的工程能力。

- **运行形态**：Vue 3 门户 + 网关 + 八个业务服务 + 运维控制台，共十个可部署服务；
  服务之间通过 Nacos 发现，前端只访问门户公开入口。
- **技术基线**：Java 25（虚拟线程）、Spring Boot 4.0.3、Spring Framework 7、
  Spring Cloud 2025.1.0、Spring Cloud Alibaba 2025.1.0.0、Vue 3.4。
- **数据与中间件**：MySQL 8.4、Redis 8.8、Elasticsearch 9.5、Silo（MinIO 兼容）、
  Nacos、RocketMQ、Kafka、Seata、Flowable、Neo4j。
- **安全基线**：OAuth2/OIDC + PKCE、服务间 mTLS、SPIFFE、OPA、每服务数据库账号、
  CA 三阶段轮换与 SVID 自动刷新。
- **当前重点**：Security Native 的 B0–B6 基线已完成；Agent Native（技能库/MCP）与
  Cloud Native（Helm/ACK）是下一步。

> 项目不是生产级产品。它追求可复现、可验证的工程判据；能力边界、触发条件与取舍
> 记录在 [ROADMAP](../ROADMAP.md)，不在这份概述里重复。

## 2. 五条 Native

| 能力线 | 本项目的定义 | 当前成熟度 | 下一步 |
|---|---|---|---|
| **Agent Native** | AI 是系统的一等执行单元，不是附加功能 | 对话、RAG、受控工具编排、知识图谱已落地 | 技能库（SKILL）、MCP 客户端、Agent Graph |
| **Cloud Native** | 运行环境由声明式配置定义，可复现、可审计 | 本地 Compose 全量环境已就位 | Helmfile + ACK、HPA、Argo CD、GraalVM Native |
| **Security Native** | 每次调用都被验证，不因来自内网而信任 | OAuth2/OIDC、mTLS/SPIFFE、OPA、证书轮换已完成 | Token Exchange、多客户端会话、微信小程序身份 |
| **Micro Service Native** | 服务边界由领域模型驱动，并且边界质量可验证 | 拆分、治理、Seata AT/TCC、outbox 已完成 | 契约测试、EventStorming 边界复盘、分库分表 |
| **SRE Native** | 告警和运维动作由 SLO/错误预算驱动 | 指标、日志、追踪、告警、备份演练已完成 | SLI/SLO、燃烧率告警、Trace-Log 联动、成本观测 |

完整条目、触发条件与验收判据见 [ROADMAP](../ROADMAP.md)。五条线共享同一套服务与基础设施，
不为练手另起平行栈。

## 3. 业务能力

- **系统与组织**：用户、角色、菜单、部门树、岗位、字典、参数；RBAC 与五级数据权限；
  仪表板、趋势统计与 Excel 导出。
- **消息与通知**：站内消息、公告、模板、多渠道投递（站内/邮件/钉钉/短信）、
  SSE 单播/组播/广播与集群广播、内容全文检索。
- **文件与检索**：上传、下载、预览、分类；Silo / 本地 / OSS 三种存储实现；
  Elasticsearch 内容检索。
- **审批与任务**：Flowable 8 请假审批、审批中心、驳回归档；Quartz 集群任务；
  备份与恢复演练。
- **监控与运维**：登录/操作/运行日志、在线会话与强制下线、服务与中间件资源检查、
  旁路运维控制台。
- **AI 工作台**：多轮流式对话、知识库 RAG（BM25 + kNN + RRF）、受控智能体工具、
  组织与 RBAC 知识图谱、每日配额与 token 观测。
- **开发者 CLI**：授权码 + PKCE 登录、多 context、只读查询、运维写命令、
  个人访问令牌（PAT）与 `iboot api` 逃生口。

按模块展开的功能说明见 [04-功能模块](./04-功能模块.md)。

## 4. 技术选型理由

### 4.1 后端

| 技术 | 选型理由 |
|---|---|
| Spring Boot 4.0.3 + Java 25 | 当前稳定线；虚拟线程承载高并发 I/O；不为迁就旧生态回退到已 EOL 的 Boot 3.5 |
| Spring Security 7 | OAuth2/OIDC、资源服务器验签、方法级授权与 RBAC 的成熟底座 |
| Spring Cloud 2025.1.0 + SCA 2025.1.0.0 | 首个支持 Boot 4.0.x 的 SCA 版本线；Nacos / Sentinel / Seata 一次对齐 |
| MyBatis 4 + PageHelper + Druid | SQL 可控、分页与连接池成熟；复杂查询不被迫绕 ORM |
| Redis + Caffeine | 二级缓存：本地命中低延迟，Redis 承担分布式一致性与 Pub/Sub 失效广播 |
| Elasticsearch 9 | 内容检索与知识库 `dense_vector` 混合检索复用同一套索引能力 |
| Silo（MinIO 兼容） | S3 兼容、可本地可云端；通过存储策略抽象切换本地磁盘与 OSS |
| Nacos 3.3.0 / Sentinel / Seata | 注册配置、治理与分布式事务的既有基础设施；规则以 Nacos 为唯一持久化来源 |
| RocketMQ + 生产方 outbox | 业务事件与本地事务绑定、可重放、有死信；broker 停机不阻断审批 |
| Kafka 4.4.0 | 只做日志缓冲，不与业务事件共用 broker，避免故障半径与语义混用 |
| OPA + SPIRE | 服务间授权集中决策 + SPIFFE 工作负载身份；本地与 Compose 使用同一套证书链路 |
| Spring AI 2.0.1 + AgentScope Java 2.0.1 | Java 原生 AI 栈；不引入仅 M 版预发布的 Spring AI Alibaba，也不在 Java 服务旁再起 Python 服务 |
| Flowable 8 | 唯一支持 Boot 4 的 Flowable 版本线；流程编排不再自建状态机 |

### 4.2 前端

| 技术 | 选型理由 |
|---|---|
| Vue 3 + TypeScript + Vite | 组合式 API、类型安全、快速构建与热更新 |
| Element Plus | 后台管理组件齐全，表格、表单与弹窗覆盖主要场景 |
| Pinia + Vue Router | 轻量状态管理与嵌套路由；路由守卫承载菜单级权限 |
| vue-i18n + axios | 中英文语言包与统一请求封装；与后端 `MessageSource` 对齐 |

完整版本矩阵与选型细节见 [02-技术栈](./02-技术栈.md)；版本锁定与升级约束见
[ROADMAP §9](../ROADMAP.md#9-版本矩阵)。

## 5. 业务价值与技术价值

### 5.1 业务价值

- 统一的后台管理平台，覆盖组织、权限、消息、文件、审批、任务、监控与统计，
  降低重复建设成本。
- RBAC 与五级数据权限、登录/操作/运行日志与审计，满足日常管理与合规检查。
- 文件、消息、审批与 AI 工作台以独立服务承载，单项能力可以独立演进与扩缩容。

### 5.2 技术价值

- **微服务边界可验证**：表所有权、跨服务调用清单、表级只读契约与回归脚本共同约束拆分质量。
- **零信任默认开启**：mTLS、SPIFFE、路径级授权、OPA、每服务凭据与轮换自动化，
  而不是把安全留成上线前的补丁。
- **AI 工具治理闭环**：工具白名单、写操作二次确认、审计与确定性回放；
  RAG 检索继承用户 RBAC 与数据权限。
- **可观测与 SRE 同栈**：指标、日志、追踪、告警与备份演练共用一套 Compose 环境，
  后续 SLO/燃烧率不另起中间件。
- **可复现的工程闭环**：`dev-init.sh` 一键拉起、全栈回归、CLI/PAT 与 OpenSpec 变更记录，
  让「做过」有证据、可重复。
