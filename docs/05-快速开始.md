## 后端启动

### 5.4 克隆项目

```bash
git clone <repository-url>
cd iboot
```

后续命令默认在仓库根目录执行；多服务启动统一由 `scripts/dev-init.sh` 负责。

### 5.5 配置数据库

创建 MySQL 数据库：
```sql
CREATE DATABASE iboot DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'iboot'@'localhost' IDENTIFIED BY 'iboot123';
GRANT ALL PRIVILEGES ON iboot.* TO 'iboot'@'localhost';
FLUSH PRIVILEGES;
```

### 5.6 配置文件

**开发环境配置（application-dev.yml）：**

修改 `iboot-system/src/main/resources/application-dev.yml`：

```yaml
spring:
  # 数据源配置
  datasource:
    type: com.alibaba.druid.pool.DruidDataSource
    druid:
      driver-class-name: com.mysql.cj.jdbc.Driver
      url: jdbc:mysql://localhost:3306/iboot?useUnicode=true&characterEncoding=utf8&useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true
      username: iboot
      password: iboot123
      # 连接池配置
      initial-size: 5
      min-idle: 5
      max-active: 20
      max-wait: 60000

  # Redis 配置
  data:
    redis:
      host: localhost
      port: 6379
      password:
      database: 0
      timeout: 10s
      lettuce:
        pool:
          min-idle: 0
          max-idle: 8
          max-active: 8

  # 迁移由 iboot-db-init 统一执行，服务不再自带 Flyway
  flyway:
    enabled: false

# 服务器配置
server:
  port: 8080

# JWT 配置
jwt:
  secret: dev-secret-key-for-jwt-token-generation-minimum-256-bits
  expiration: 604800        # 7 天（秒）
  session-timeout: 30       # 30 分钟滑动过期

# 日志配置
logging:
  level:
    root: INFO
    com.iboot.system: DEBUG
    org.mybatis: DEBUG
  file:
    name: logs/iboot-system.log
```

**生产环境配置（使用环境变量）：**

```yaml
spring:
  datasource:
    druid:
      url: jdbc:mysql://${DB_HOST}:${DB_PORT:3306}/${DB_NAME:iboot}
      username: ${DB_USERNAME}
      password: ${DB_PASSWORD}
  data:
    redis:
      host: ${REDIS_HOST}
      password: ${REDIS_PASSWORD}

jwt:
  secret: ${JWT_SECRET}
```

### 5.7 数据库迁移

数据库的建库与全部迁移由 `iboot-db-init` 统一执行，服务进程不再执行迁移。

**迁移脚本位置：**

```
iboot-db-init/src/main/resources/db/migration/
└── V1__baseline.sql            # 单库结构与种子数据
```

**手动执行：**

```bash
mvn -pl iboot-db-init -am package
MYSQL_HOST=localhost MYSQL_PORT=3306 MYSQL_USERNAME=root MYSQL_PASSWORD=root \
  java -jar iboot-db-init/target/iboot-db-init-1.0.0-exec.jar
```

### 5.8 启动后端

**推荐：一键启动**
```bash
scripts/dev-init.sh
```

脚本会启动中间件与 Sentinel Dashboard、写入基线规则、按需构建、执行 `iboot-db-init`、
按顺序启动九个业务服务与运维控制台，并等待健康。
内网或镜像环境可在 `mvn` 后追加 `-s <settings.xml>`；`dev-init.sh` 会优先使用
`$MAVEN_SETTINGS`，未设置时自动使用 `$HOME/repo/settings.xml`（若存在）。

集中日志链路（Kafka → Logstash → Elasticsearch）不在一键启动范围内：需要时先
`docker compose -f docker/docker-compose.yml up -d kafka kafka-init logstash`，再按
[docs/11 §11.11.1](./11-可观测性设计.md) 打开投递开关。

**只启动单个服务（调试）**
```bash
mvn -pl iboot-system spring-boot:run
```

**运行 JAR 包**
```bash
mvn -pl iboot-system -am package -DskipTests
java -jar iboot-system/target/iboot-system-1.0.0.jar
```

**使用 IDEA 启动**
主类为 `com.iboot.system.IBootSystemApplication`；多服务联调仍建议使用 `dev-init.sh`，避免只启动系统服务时其它服务不可达。

### 5.8.1 启动 AI 服务

AI 工作台是独立服务（8081），需要 Redis、MySQL（共享库 `iboot`）、Elasticsearch、MinIO 与 `iboot-system` 已启动。

1. 在根目录 `.env` 中配置百炼与知识库变量：

```ini
DASHSCOPE_CHAT_API_KEY=sk-...
DASHSCOPE_EMBEDDING_API_KEY=sk-...
DASHSCOPE_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode

MYSQL_HOST=localhost
MYSQL_PORT=3306
MYSQL_USERNAME=root
MYSQL_PASSWORD=root
IBOOT_AI_MYSQL_DATABASE=iboot
ELASTICSEARCH_URIS=http://localhost:9200
IBOOT_AI_MINIO_ENDPOINT=http://localhost:9000
IBOOT_AI_MINIO_ACCESS_KEY=minioadmin
IBOOT_AI_MINIO_SECRET_KEY=minioadmin
IBOOT_AI_MINIO_BUCKET=iboot-ai
IBOOT_AI_RAG_ENABLED=true
```

2. 创建 MinIO `iboot-ai` bucket（命令见 [22-AI 工作台操作指南](./22-AI 工作台操作指南.md)）。

3. 启动服务：

```bash
set -a; source .env; set +a
mvn -pl iboot-ai spring-boot:run
```

4. 验证：

```bash
curl localhost:8081/actuator/health
```

登录前端后进入「AI 工作台 → 智能对话」或「知识库」。iboot-system 执行 `V25` 菜单迁移后需重新登录。完整配置与排障见 [22-AI 工作台操作指南](./22-AI 工作台操作指南.md)。

知识图谱（1.4）为可选能力，默认关闭：先 `docker compose --profile graph up -d neo4j`，再把 `IBOOT_AI_GRAPH_ENABLED` 置为 `true` 启动 `iboot-ai`，然后以超管登录态调用 `POST /api/ai/graph/sync` 完成入图，详见 [22-AI 工作台操作指南](./22-AI 工作台操作指南.md) §13。

### 5.11 后端启动验证

**验证步骤：**

1. **检查进程是否运行**
   ```bash
   jps -l | grep iboot
   # 应显示类似：12345 com.iboot.system.IBootSystemApplication
   ```

2. **检查端口监听**
   ```bash
   netstat -tlnp | grep 8080
   # 应显示：tcp  0  0 0.0.0.0:8080  0.0.0.0:*  LISTEN  12345/java
   ```

3. **检查日志文件**
   ```bash
   tail -f logs/iboot-system.log
   # 应看到应用启动成功的日志
   ```

4. **测试认证端点**
   ```bash
   # OIDC 发现文档：经网关访问认证服务
   curl -sS http://localhost:8088/.well-known/openid-configuration \
     | jq '{issuer, authorization_endpoint, token_endpoint, jwks_uri}'

   # 双栈窗口内仍可使用旧的用户名密码接口；窗口关闭后该接口会被移除
   curl -X POST http://localhost:8088/api/auth/login \
     -H "Content-Type: application/json" \
     -d '{"username":"admin","password":"admin123456"}'
   ```
   浏览器登录走授权码 + PKCE：未登录访问门户时会被跳转到认证服务的登录页（`http://localhost:8088/login`），
   登录成功后回到原先要访问的页面。

5. **检查 Sentinel 治理组件**
   - Dashboard：<http://localhost:8858>（本地开发默认关闭登录）；
   - 基线规则：`bash scripts/sentinel-init.sh --verify`；
   - 规则与演练说明见 [23-微服务底座操作指南 §13](./23-微服务底座操作指南.md)。

### 5.12 配置文件

**开发环境配置（.env）：**

修改 `iboot-portal/.env` 文件：

```bash
# 应用标题
VITE_APP_TITLE=iBoot 管理系统

# API 基础路径
VITE_API_BASE_URL=/iboot/api

# 是否启用 sourcemap
VITE_SOURCE_MAP=true

# 版本号
VITE_APP_VERSION=1.0.0
```

**代理配置（vite.config.ts）：**

```typescript
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import { resolve } from 'path'

export default defineConfig({
  plugins: [vue()],
  resolve: {
    alias: {
      '@': resolve(__dirname, 'src')
    }
  },
  server: {
    port: 3000,
    host: true,
    proxy: {
      '/iboot/api': {
        target: 'http://localhost:8080',
        changeOrigin: true,
        rewrite: (path) => path.replace(/^\/iboot\/api/, '/api')
      }
    }
  },
  css: {
    preprocessorOptions: {
      scss: {
        additionalData: `@use "@/styles/variables.scss" as *;`
      }
    }
  },
  build: {
    outDir: 'dist',
    minify: 'terser',
    terserOptions: {
      compress: {
        drop_console: true,
        drop_debugger: true
      }
    },
    rollupOptions: {
      output: {
        manualChunks: {
          'vue-vendor': ['vue', 'vue-router', 'pinia'],
          'element-plus': ['element-plus'],
          'echarts': ['echarts']
        }
      }
    }
  }
})
```

## Docker 部署

全栈容器化由 `scripts/docker-deploy.sh` 与 `docker/docker-compose.yml` 负责；镜像构建、服务清单、端口与排障的权威说明见 [`docker/README.md`](../docker/README.md)。

### 5.20 启动所有服务

```bash
# 核心 + 可观测性（默认）
scripts/docker-deploy.sh up

# 只启动核心组件
scripts/docker-deploy.sh up core
```

该命令会构建后端与前端镜像、启动 Compose，并轮询服务健康状态。

### 5.21 检查服务状态

```bash
scripts/docker-deploy.sh status
```

### 5.22 查看日志

```bash
scripts/docker-deploy.sh logs iboot-system
```

### 5.23 停止服务

```bash
scripts/docker-deploy.sh down
```

### 5.24 清理数据

```bash
scripts/docker-deploy.sh purge --yes
```

> **警告：** 此操作会删除所有持久化数据卷，请谨慎使用。

### 5.25 构建 Docker 镜像

后端使用共享模板 `docker/Dockerfile.backend`，数据库初始化使用 `docker/Dockerfile.dbinit`，前端使用 `iboot-portal/Dockerfile`；`docker-deploy.sh up` 已包含构建步骤，无需手工 `docker build`。

### 5.26 使用 Docker 启动应用

所有服务由 Compose 编排，不再单独 `docker run`；私有配置通过根目录 `.env` 注入。

## 常见问题

### 5.27 后端启动失败

**问题 1：端口被占用**
```
Port 8080 was already in use.
```

**解决方案：**
```bash
# 查找占用端口的进程
lsof -i :8080
# 杀死进程
kill -9 <PID>

# 或修改配置更换端口
server:
  port: 8081
```

**问题 2：数据库连接失败**
```
com.mysql.cj.jdbc.exceptions.CommunicationsException: Communications link failure
```

**解决方案：**
1. 检查 MySQL 是否启动：`docker ps | grep mysql` 或 `systemctl status mysqld`
2. 检查数据库连接配置是否正确
3. 检查防火墙设置

**问题 3：Redis 连接失败**
```
io.lettuce.core.RedisConnectionException: Unable to connect to localhost:6379
```

**解决方案：**
1. 检查 Redis 是否启动：`docker ps | grep redis` 或 `systemctl status redis`
2. 检查 Redis 配置：`redis-cli ping` 应返回 `PONG`

### 5.28 前端启动失败

**问题 1：依赖安装失败**
```
npm ERR! code ERESOLVE
```

**解决方案：**
```bash
# 清理缓存
cnpm cache clean --force
# 删除 node_modules
rm -rf node_modules package-lock.json
# 重新安装
cnpm install
```

**问题 2：开发服务器启动失败**
```
Error: listen EADDRINUSE: address already in use 0.0.0.0:3000
```

**解决方案：**
```bash
# 查找占用端口的进程
lsof -i :3000
# 杀死进程
kill -9 <PID>

# 或修改 vite.config.ts 更换端口
server: {
  port: 3001
}
```

**问题 3：代理请求失败**
```
Error: connect ECONNREFUSED 127.0.0.1:8080
```

**解决方案：**
1. 确认后端服务已启动
2. 检查代理配置 `vite.config.ts` 中的 `target` 地址
3. 检查后端服务监听的地址和端口

### 5.29 Docker 相关问题

**问题 1：容器启动失败**
```
Error starting userland proxy: listen tcp4 0.0.0.0:3306: bind: address already in use
```

**解决方案：**
```bash
# 停止本地 MySQL 服务
sudo systemctl stop mysqld

# 或修改 docker-compose.yml 更换端口
ports:
  - "3307:3306"
```

**问题 2：容器间网络不通**
```
Unable to connect to mysql:3306
```

**解决方案：**
1. 确保所有服务在同一个 Compose 网络中
2. 使用服务名而非 localhost 访问（如 `mysql` 而非 `127.0.0.1`）
3. 检查网络配置：`docker network ls`

### 5.30 登录问题

**问题：无法登录**
```
登录失败：用户名或密码错误
```

**解决方案：**
1. 确认数据库已正确初始化
2. 检查默认账号是否存在：
   ```sql
   SELECT * FROM sys_user WHERE username = 'admin';
   ```
3. 检查密码加密是否正确（BCrypt）
4. 查看后端日志定位具体错误

**问题：登录后提示无权限**
```
403 Forbidden
```

**解决方案：**
1. 检查用户是否分配了角色
2. 检查角色是否分配了菜单权限
3. 清除浏览器缓存后重新登录
