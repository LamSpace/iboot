#### 8.2.2 各层部署配置

**接口层（Interfaces Layer）部署：**
- Controller 类无需特殊配置，Spring Boot 自动扫描
- 确保 `@RestController`、`@RequestMapping` 注解正确
- Swagger 文档在生产环境可禁用

**应用层（Application Layer）部署：**
- Application Service 使用 `@Service` 注解
- 事务边界定义在应用层（`@Transactional`）
- 确保领域事件发布器正确配置

**领域层（Domain Layer）部署：**
- 领域层是纯 Java 代码，无需特殊部署配置
- 确保领域模型、值对象、仓储接口正确定义
- 领域事件监听器使用 `@EventListener`

**基础设施层（Infrastructure Layer）部署：**
- Repository 实现类使用 `@Repository` 注解
- MyBatis Mapper 使用 `@Mapper` 或 XML 配置
- 确保数据源、Redis、MinIO 等连接配置正确

## 本地开发部署

### 8.7 后端启动步骤

```bash
# 推荐：启动中间件、Sentinel Dashboard/规则、db-init、九个业务服务与运维控制台
scripts/dev-init.sh

# 只调试系统服务
mvn -pl iboot-system spring-boot:run
```

多服务依赖与健康检查由 `dev-init.sh` 处理；单独启动系统服务时，认证、通知等下游不可用属于预期。
集中日志链路（Kafka → Logstash → Elasticsearch）按需单独启动，见
[docs/11 §11.11.1](./11-可观测性设计.md)；容器清单与端口以 [docker/README](../docker/README.md) 为准。

### 8.7.1 AI 服务启动

AI 服务是独立进程（8081），需要 Redis、MySQL（共享库 `iboot`）、Elasticsearch、MinIO 与 `iboot-system` 已启动。

```bash
# 创建 schema 与 bucket（首次）
docker exec iboot-mysql mysql -uroot -proot \
  # 数据库 iboot 与表结构由 iboot-db-init 创建，无需手工建库
docker exec iboot-minio /usr/bin/mc alias set local http://localhost:9000 minioadmin minioadmin
docker exec iboot-minio /usr/bin/mc mb --ignore-existing local/iboot-ai

# 启动
set -a; source .env; set +a
mvn -pl iboot-ai spring-boot:run
```

需要注入 `DASHSCOPE_CHAT_API_KEY`、`DASHSCOPE_EMBEDDING_API_KEY`、`DASHSCOPE_BASE_URL`、共享的 `JWT_SECRET`，以及 MySQL/Elasticsearch/MinIO 与 `IBOOT_AI_RAG_ENABLED`。OCR 默认关闭，启用时额外注入 `DASHSCOPE_OCR_API_KEY`。1.1/1.2 不做容器化；完整配置与排障见 [22-AI 工作台操作指南](./22-AI 工作台操作指南.md)。

### 8.9 本地数据库初始化

数据库 `iboot` 与全部表结构由 `iboot-db-init` 创建，`scripts/dev-init.sh` 会自动执行。手工执行：

```bash
MYSQL_HOST=localhost MYSQL_PORT=3306 MYSQL_USERNAME=root MYSQL_PASSWORD=root \
  java -jar iboot-db-init/target/iboot-db-init-1.0.0-exec.jar
```

业务服务不再执行 Flyway（`spring.flyway.enabled=false`），迁移脚本集中在
`iboot-db-init/src/main/resources/db/migration/`。

## Docker 容器化部署

### 8.10 Docker Compose 配置

全栈编排以 `docker/docker-compose.yml` 为准；服务清单、端口、卷、启动顺序与排障见
[`docker/README.md`](../docker/README.md)。本指南不复制 Compose 全文，避免与实现漂移。

`sentinel-dashboard`（8858）是必选治理组件。本地 compose 默认关闭登录；非本地环境必须叠加
`docker/docker-compose.prod.yml` 并注入 `SENTINEL_DASHBOARD_USER` / `SENTINEL_DASHBOARD_PASSWORD`，
缺失时 compose 会直接失败。`docker-deploy.sh up` 在服务健康后调用
`scripts/sentinel-init.sh` 写入 Nacos 基线规则；手动校验用 `bash scripts/sentinel-init.sh --verify`。

### 8.11 后端 Dockerfile

后端统一使用共享模板 `docker/Dockerfile.backend`：BuildKit 先由
`docker/Dockerfile.backend-builder` 完成一次 Maven reactor 构建，运行期镜像只包含 JRE、
模块 jar 与 `script/run-java.sh`。不再存在模块级 `iboot-*/Dockerfile`。

### 8.12 前端 Dockerfile

前端使用 `iboot-portal/Dockerfile`：`node:22-bookworm-slim` 构建 `dist`，再拷贝到 nginx
运行期镜像。

### 8.13 前端 Nginx 配置

生产配置以 `iboot-portal/nginx.conf` 为准：`/iboot/api` 代理到 `iboot-gateway:8088`，
并额外代理 `/iboot/ai`、`/druid`、`/sba` 与 Swagger 等同源路径。新增后端同源路径时必须
同步补充代理，否则 SPA 回退会把 `index.html` 返回给 JSON 请求。

### 8.14 Docker 部署步骤

```bash
scripts/docker-deploy.sh up          # 构建并启动（默认核心 + 可观测性）
scripts/docker-deploy.sh status
scripts/docker-deploy.sh logs iboot-system
scripts/docker-deploy.sh down
```

首次构建需要下载 Maven 与 npm 依赖，通常 10–15 分钟；后续利用 BuildKit 缓存通常 3–5 分钟。

## 生产环境部署

### 8.15 Nginx 生产配置

```nginx
upstream gateway {
    least_conn;
    server 192.168.1.100:8088 weight=3;
    server 192.168.1.101:8088 weight=2;
    server 192.168.1.102:8088 weight=1;
    keepalive 32;
}

server {
    listen 80;
    server_name your-domain.com;

    # HTTP 重定向到 HTTPS
    return 301 https://$server_name$request_uri;
}

server {
    listen 443 ssl http2;
    server_name your-domain.com;

    # SSL 证书配置
    ssl_certificate /etc/nginx/ssl/your-domain.crt;
    ssl_certificate_key /etc/nginx/ssl/your-domain.key;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers HIGH:!aNULL:!MD5;
    ssl_prefer_server_ciphers on;

    # 前端静态文件
    location / {
        root /var/www/iboot-portal;
        index index.html;
        try_files $uri $uri/ /index.html;

        # 浏览器缓存
        location ~* \.(jpg|jpeg|png|gif|ico|css|js|svg|woff|woff2|ttf|eot)$ {
            expires 1y;
            add_header Cache-Control "public, immutable";
        }
    }

    # API 反向代理：统一经网关；SSE 需要长连接超时
    location /iboot/api {
        proxy_pass http://gateway;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_cache_bypass $http_upgrade;
        proxy_connect_timeout 60s;
        proxy_send_timeout 60s;
        proxy_read_timeout 3600s;   # SSE 长连接
        proxy_buffering off;
    }

    # 访问日志
    access_log /var/log/nginx/iboot-access.log;
    error_log /var/log/nginx/iboot-error.log;

    # 开启 Gzip
    gzip on;
    gzip_vary on;
    gzip_min_length 1024;
    gzip_proxied any;
    gzip_comp_level 6;
    gzip_types text/plain text/css text/xml text/javascript application/json application/javascript application/xml+rss application/rss+xml font/truetype font/opentype application/vnd.ms-fontobject image/svg+xml;
}
```

## CI/CD 部署

### 8.18 GitHub Actions 配置

仓库现有 CI 见 `.github/workflows/regress.yml`：PR 阶段执行路由覆盖、构建与网关测试，
定时任务执行全栈回归。构建命令统一走 `scripts/build.sh`，镜像使用
`docker/Dockerfile.backend` 共享模板；不再维护只构建单个模块的流水线。

### 8.19 Jenkins Pipeline

如使用 Jenkins，建议按以下阶段组织：

```groovy
stage('Build')  { steps { sh 'scripts/build.sh' } }
stage('Image')  { steps { sh 'scripts/docker-deploy.sh up' } }
stage('Verify') { steps { sh 'scripts/regress/regress.sh' } }
```

镜像构建参数为 `--build-arg MODULE=<module>`；不要在流水线中引用已删除的模块级
`iboot-*/Dockerfile`。

### 8.23 备份策略

**数据库备份脚本：**

```bash
#!/bin/bash

BACKUP_DIR="/backup/mysql"
DATE=$(date +%Y%m%d_%H%M%S)
DB_NAME="iboot"
DB_USER="root"
DB_PASS="root"

# 创建备份目录
mkdir -p $BACKUP_DIR

# 备份数据库
mysqldump -u$DB_USER -p$DB_PASS $DB_NAME > $BACKUP_DIR/iboot_$DATE.sql

# 压缩备份文件
gzip $BACKUP_DIR/iboot_$DATE.sql

# 删除 30 天前的备份
find $BACKUP_DIR -name "iboot_*.sql.gz" -mtime +30 -delete

echo "Backup completed: iboot_$DATE.sql.gz"
```

## 常见问题

### 8.24 启动问题

**问题 1：端口被占用**

```
Error: Port 8080 was already in use.
```

**解决方案：**
```bash
# 查找占用端口的进程
lsof -i :8080
netstat -tlnp | grep 8080

# 杀死进程
kill -9 <PID>

# 或修改配置
server.port=8081
```

**问题 2：数据库连接失败**

```
com.mysql.cj.jdbc.exceptions.CommunicationsException: Communications link failure
```

**解决方案：**
1. 检查 MySQL 是否启动
2. 检查数据库连接配置
3. 检查防火墙设置
4. 检查数据库用户权限

### 8.25 性能问题

**问题：应用启动慢**

**解决方案：**
```bash
# 增加 JVM 堆内存
JAVA_OPTS="-Xms2g -Xmx4g"

# 启用懒加载
spring.jpa.properties.hibernate.enable_lazy_load_no_trans=true

# 优化数据库连接池
spring.datasource.hikari.maximum-pool-size=20
spring.datasource.hikari.minimum-idle=5
```

### 8.26 Docker 问题

**问题：容器无法启动**

```
Error starting container: address already in use
```

**解决方案：**
```bash
# 查看端口占用
docker compose -f docker/docker-compose.yml ps
netstat -tlnp

# 停止冲突的服务
docker compose -f docker/docker-compose.yml down

# 修改端口映射
# 编辑 docker/docker-compose.yml，将端口改为未被占用的端口
```
