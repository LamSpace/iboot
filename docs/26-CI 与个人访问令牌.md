# 26-CI 与个人访问令牌

> 适用版本：iBoot 1.0.0。PAT 由认证服务签发，资源服务离线验签；CI 只经公开入口的
> `/api`（门户反代到网关）调用既有接口，不绕过权限、数据范围与审计。

## 1. 适用场景

- 定时触发备份、执行任务或巡检；
- 发布后验证接口与权限；
- 本地智能体在无浏览器环境中排障。

PAT 是长期凭据，不应用于替代用户日常登录。浏览器内的操作仍使用门户或
`iboot login` 的交互式会话。

## 2. 准备令牌

在已登录的开发者终端签发（有效期默认 30 天，最长 90 天）：

```bash
./bin/iboot login
./bin/iboot token create github-actions --expires-days 30 \
  --scope backup:record:create --scope backup:record:list --yes
```

`--scope` 可重复，必须是当前用户已有权限的子集；不指定时继承全部权限。上例只允许
触发备份与查询备份记录，流水线不需要用户管理或文件管理权限。命令输出的 `token`
字段只出现一次，立即保存到 CI secret。`token list` 只显示元数据：

```bash
./bin/iboot token list
```

为 CI 使用单独的低权限账号，只授予流水线需要的权限（例如备份与任务查询），不要复用
管理员账号。

## 3. 保存为 CI secret

GitHub Actions 在仓库或 Environment 的 **Settings → Secrets and variables → Actions**
中新增 `IBOOT_PAT`，不要把令牌写进工作流文件。若使用 Environment，建议同时配置
required reviewers，避免任意分支读取生产凭据。

## 4. GitHub Actions 示例

```yaml
name: iboot-ops

on:
  workflow_dispatch:
  schedule:
    - cron: '0 18 * * *' # UTC 18:00，按需调整

jobs:
  backup:
    runs-on: ubuntu-latest
    env:
      IBOOT_CONFIG_DIR: ${{ runner.temp }}/iboot
      IBOOT_GATEWAY: ${{ vars.IBOOT_GATEWAY }}
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: '25'

      - name: Build CLI
        run: mvn -B -pl iboot-cli package

      - name: Point CLI at the gateway
        run: ./bin/iboot config add ci --base-url "$IBOOT_GATEWAY" --use

      - name: Trigger backup and wait
        env:
          IBOOT_PAT: ${{ secrets.IBOOT_PAT }}
        run: |
          printf '%s' "$IBOOT_PAT" | ./bin/iboot backup trigger --wait --yes --token-stdin
```

说明：

- `IBOOT_GATEWAY` 必须是 HTTPS 公开入口；CLI 会拒绝非 loopback 的 `http://` base URL。
  目标环境使用私有 CA 时，额外设置 `IBOOT_CLI_TRUSTSTORE` 指向 PKCS12 信任库；
- `--token-stdin` 从标准输入读取令牌，优先级高于 `IBOOT_TOKEN` 与本地凭据，且不会
  写入凭据文件；
- `--wait` 轮询备份记录直到 `SUCCESS` / `FAILED`，默认 2 秒间隔、300 秒超时；
- 退出码可用于后续步骤判断：`0` 成功、`3` 认证失效、`4` 越权、`5` 网络或 5xx、
  `6` 业务错误、`7` 缺少 `--yes`。

如果流水线使用预构建的 CLI jar，可跳过构建步骤并设置 `IBOOT_CLI_JAR` 指向 jar 路径。

## 5. 轮换与撤销

1. 签发新令牌（同名或带日期后缀），更新 CI secret；
2. 触发一次只读命令确认新令牌可用；
3. 撤销旧令牌：`./bin/iboot token revoke <id> --yes`；
4. 在操作日志中确认签发与撤销记录。

令牌到期前主动轮换，避免流水线在到期当天失败。

## 6. 生命周期与权限

- 用户停用或删除时，该用户全部 PAT 立即失效，不需要逐个撤销；
- 管理员在在线列表强退某个会话不会撤销 PAT；需要撤销 PAT 时使用 `token revoke`；
- PAT 的权限是签发时快照：角色或权限调整后，撤销并重建 PAT 才会生效；
- 每用户最多 10 个活动令牌，长期不用的令牌应及时撤销。

操作日志中的 `authType` 会标记 `PAT`，与人工操作的 `SESSION` 区分；可用
`iboot log operate --json` 或门户操作日志页核对流水线行为。

## 7. 常见问题

| 现象 | 处理 |
|---|---|
| 401 | 令牌已过期、已撤销，或用户被停用/删除；重新签发 |
| 403 | 账号缺少接口权限；按最小权限原则调整角色，不要换用管理员令牌 |
| 连接失败 | 确认 CI 能访问 HTTPS 公开入口，且 `IBOOT_GATEWAY` 是 HTTPS 地址 |
| 证书校验失败 | 目标环境使用私有 CA 时设置 `IBOOT_CLI_TRUSTSTORE`；不要用 `-k` 或取消校验 |
| 备份功能未启用 | 目标环境关闭了备份；这是部署配置，不是令牌问题 |
| 令牌泄漏 | 立即 `token revoke`；必要时停用用户以撤销其全部 PAT，再重新签发 |

更多命令与退出码见 [25-开发者 CLI 操作指南](<./25-开发者 CLI 操作指南.md>)。
