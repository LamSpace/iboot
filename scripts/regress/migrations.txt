# 服务迁移登记：<路径前缀> <源服务> <目标服务>
#
# 每把一个接口从一个服务迁到另一个服务，就在这里登记一行。
# path-conservation.sh 同时校验三件事：
#   1. 全部服务快照的路径并集在迁移前后完全相同（消失或凭空出现都失败）；
#   2. 登记的前缀在目标服务中确实存在；状态为 done 时还要求源服务已不再出现；
#   3. 并集发生变化时，变化必须能由登记的迁移解释。
#
# 服务名使用快照文件名（golden/<service>.json 去掉扩展名），即 admin / ai / file。
# 第四列是迁移状态：
#   transitional — 源服务仍保留旧实现（绞杀者过渡期），只校验目标服务已有该前缀；
#   done         — 旧实现已删除，源服务不得再出现该前缀。
/api/file admin file done
# 消息与通知：过渡期管理端仍保留旧实现（绞杀者），路由已指向 iboot-notify；
# 第二个变更 remove-notify-from-admin 删除旧实现后，逐条改为 done。
/api/message admin notify done
/api/notice admin notify done
/api/notification admin notify done
/api/push admin notify done
/api/search admin notify done
# 认证接口：只迁登录/登出/注册。GET /api/auth/scope 仍在 admin（数据权限范围属系统域），
# 因此这里逐条登记，而不是登记 /api/auth 前缀——后者永远无法达到 done。
# `/api/auth/login` 不在这里登记：它随 OAuth2 协议切换整体下线（不是搬家到别的服务），
# 认证入口已由 `/oauth2/authorize` 承担。登出与注册是功能而非登录协议，仍在认证服务中。
/api/auth/logout admin auth done
/api/auth/register admin auth done
# OAuth2 / OIDC 端点与登录页是本次新增的外部接口，不属于搬家。
# 这里以 admin 作为名义来源登记，使「凭空出现」的检查仍然生效：
# 目标服务确实有这些路径、来源服务确实没有，路径守恒才能通过。
/login admin auth done

# 调度服务：remove-job-from-admin 已删除管理端旧实现，两条登记收敛为 done。
# 备份路径必须按路径登记而不是 /api/monitor 前缀——后者会覆盖尚未拆分的监控接口。
/api/job admin job done
/api/monitor/backup admin job done

# 审批工作流：add-workflow-service 期间管理端保留旧实现，路由已指向 workflow；
# remove-workflow-from-admin 删除旧实现后改为 done。
/api/approval admin workflow done
